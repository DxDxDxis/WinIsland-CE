# 归档规则、来源与完整性

## 当前整理范围

- 原始目录：`E:\aaAAx项目`，其中多数后期版本来自 `WinIsland-社区版-大更新/release`。
- 归档目标：`I:\gtb开源`。
- 本轮只读取原始文件，复制内容并逐项 SHA-256 校验；没有修改、移动、重命名原始源码或 EXE。
- 所有新增 README、清单、图片副本、发布辅助脚本和许可证均写入目标目录。

## 正式版号与筛选

正式目录名使用 `Winlsland-` 前缀；纯数字正式版追加“社区版”，alpha/beta 和明确的 r1/c1/c2 保留原阶段编号。`fixed`、`path-state-fix`、`outward`、快照日期等内部构建后缀不作为正式版号。

**每个正式版号只选择最新一次可找到的构建。** PE 主 EXE 的 COFF 链接时间是主要比较依据，结合源码 Version/BuildId、原 manifest 与成品哈希核验。目录修改时间、目录名都不能独自证明是最新成品。相同 EXE 哈希的多个副本只保留一个可关联源码的来源。

`catalog/build-candidates.json` 保存候选构建记录，`catalog/versions.json` 保存所选版本及来源，`docs/VERSIONS.md` 按新到旧排列。候选来源中的修复后缀只用于追溯，不在正式产品版本名中显示。

## 已确认的历史差异

- 1.1.1 社区版的原发布说明记载：只改发布文件名，内部仍为 1.1.0.0；同时提供原 EXE 相同哈希的证据。
- 名叫 `WinIsland-1.1.2社区版` 的工作区实际 `AppVersion.cs` 已为 1.2.2beta，因此源码归入 1.2.2beta。
- 1.1.2、1.2.0、1.2.1beta 未找到独立完整对应的源码快照，仅保留确认的成品及原说明，不拿新源码填充。
- 1.2.3beta 源码来自原源码 ZIP；同名工作区当前代码已为 1.2.3beta_2，所以两者分开。
- alpha2 的历史 ZIP 包含多个 r 修订运行目录；选最新 r4，包内没有源码。另一个原生工作区 README 写 alpha2、core.h 却声明 alpha-r1，不能据此认定它是 alpha2 成品源码。
- 最新 1.3.1alpha 使用已记录的正式 release EXE，不使用仍被运行进程占用的中间 build EXE。

## 复制内容与排除内容

保留：源码、头文件、资源、构建脚本、锁文件、SDK、插件开发示例、原 README/docs、第三方源码及许可，以及所选成品的必要运行依赖。

排除：node_modules、SDK 安装器/工具缓存、`.git` 历史、对象文件、PDB、临时测试输出、运行日志、浏览器缓存、真实通知数据库、用户设置、插件启用记录、IPC 连接凭据及旧副构建。测试代码保留，测试运行生成的数据目录不作为源码分发。原 source 中的 tools 脚本可保留，安装在 tools 中的整套编译工具不打包。

由于整理中途按用户要求从“保留所有修订”调整为“每版只选最新”，先前尚未完成的目标端草稿被隔离在 `.organizing-drafts/`，不属于正式归档、不出现在版本索引，Git 忽略且发布脚本不会包含它。原始 E 盘目录未受影响。

## 校验文件

- `catalog/copied-files.json`：原工作区相对路径、目标相对路径、大小、SHA-256。
- `catalog/versions.json`：正式版号、所选来源、源码证据、成品哈希。
- `catalog/images.json`：总 README 展示图片的来源及哈希。
- `catalog/verification.json`：校验结果和仍需人工确认的项目。
- `tools/verify_archive.py`：验证副本哈希、版号顺序、命名、文件完整性及关键链接。

原始文件夹的外部绝对链接、旧报告中的相对 verification 链接可能指向未纳入归档的历史测试材料。原文按字节保留，不批量重写原始文档；新的总 README 与导航文档使用归档内链接。没有伪造丢失的测试证据。

## 本轮没有宣称完成的事

没有重新编译/运行所有历史版本，没有证明全部 EXE 与所见源码字节级重现一致，没有把第三方组件改授 BSD，没有上传 GitHub，没有创建远程 Release。最新版的既有运行测试报告仍属于原工程的上一轮验证；本轮验收是版本筛选、文件复制、哈希、文档导航与发布准备。
