# 1.2.5alpha 大尺寸贴顶更新

构建标识：`1.2.5alpha-top-docked-20260912-r3`。工作目录是 `WinIsland-社区版-大更新`，原 `1.2.4beta_2` 目录未覆盖。正式程序为 `release/1.2.5alpha-top-docked/WinIsland-1.2.5alpha.exe`，分发时复制整个 top-docked 目录。

## 外形、位置和布局

黑色容器的上沿平直，在工作区顶部无间隙贴合。两侧对称，下方两角采用圆弧。紧凑横条的下圆角半径为高度的一半；展开时平滑转为较柔和的面板圆角。容器使用一个闭合 Direct2D 几何路径填充和裁剪，不叠加阴影拼接层。关闭顶部贴合时，恢复四角圆润的悬浮轮廓及 8 DIP 顶部间距。

顶部以目标显示器 `MONITORINFOEX.rcWork.top` 为准。如果顶部存在占用工作区的任务栏或工具栏，避让这些区域，不覆盖它们。因此工作区上沿不一定等于物理屏幕的 y=0。

通过 `EnumDisplayMonitors` / `GetMonitorInfoW` 读取显示器、分辨率及工作区，`GetDpiForMonitor` 读取有效 DPI，清单声明 PerMonitorV2。处理 `WM_DPICHANGED`、`WM_DISPLAYCHANGE`、`WM_SETTINGCHANGE` 及跨显示器窗口移动。横竖屏依据实际工作区宽高重新约束。选择不存在的显示器时回退到可用显示器。拖动到另一显示器后松开可切换目标屏幕。

宽度和高度分别计算，内容使用统一等比缩放；字形与封面不会被非等比拉伸。消息仍在音乐下方展开，保留当前音乐面板状态。文字布局保留省略和换行，小屏幕下限制整体宽度；空间约束优先于用户倍率。设置改变和状态动画以当前插值尺寸为起点，可中断后继续。

## 设置及默认值

设置窗口新增“尺寸位置”分类、“大尺寸与位置”分组：

| 设置 | 默认 | 范围或行为 |
|---|---|---|
| 灵动岛缩放比例 | 1.5 | 1.0～2.0 |
| 宽度倍率 | 1.0 | 0.75～1.5 |
| 高度倍率 | 1.0 | 0.75～1.5 |
| 顶部贴合 | 开启 | 对齐工作区上沿 |
| 圆角模式 | 自动 | 自动、半圆、2/3 圆度 |
| 显示器 | 自动 | 当前显示器或手动指定设备 |
| DPI 处理 | 自动 | 可用 0.8～1.25 尺寸修正，默认 1.0 |
| 恢复默认布局 | — | 只重置上述布局项 |

圆角上限始终为最短边的一半；2/3 模式在紧凑横条中也会受此限制，不产生自交轮廓。保存立即生效，后台写入 XML，重启加载。旧配置中缺失的新项使用默认值，原音乐、通知等配置不变；拒绝负值、非数、无穷和越界值。

## 尺寸

下表单位为 DIP，适用于独立宽高倍率、DPI 修正均为 1.0，且工作区有足够空间的情况。倍率以进入大更新时的大小为基准，没有重复叠加此前 95% 缩放。按用户追加要求，r3 在贴顶版本基础上将消息区域宽高缩至 80%，无音乐/消息的待机高度缩至 90%，待机宽度不变。

| 状态 | 当前 1.0 倍 | 默认 1.5 倍 | 2.0 倍 |
|---|---:|---:|---:|
| 待机 | 171.380 × 25.582 | 257.070 × 38.372 | 342.760 × 51.163 |
| 音乐横条（无更宽歌词） | 374.009 × 39.300 | 561.013 × 58.950 | 748.017 × 78.600 |
| 展开音乐（有时间轴） | 374.009 × 98.932 | 561.013 × 148.398 | 748.017 × 197.864 |

实际像素为 DIP × 系统 DPI / 96。例如默认音乐横条在 150% DPI 下约为 842 × 88 像素，边缘抗锯齿可能占用下一像素。歌词、消息或 FPS/Ping 可改变所需宽度，始终受工作区上限约束。

追加缩小前，默认待机为 257.070 × 42.636 DIP，现在高度为 38.372 DIP。回归中的长消息从 877.800 × 125.772 DIP 缩为约 702.240 × 100.618 DIP。消息文字、内边距和下圆角一起按 80% 等比绘制，并非裁掉外部容器。音乐与消息共存时，保留上方音乐高度与控件，仅缩小消息区；整体宽度不小于音乐所需宽度。若普通模式启用 FPS/Ping，保留足够横向空间，不以缩小消息挤掉这两个指标。

## 鼠标命中与性能

渲染窗口使用 `WS_EX_LAYERED | WS_EX_TRANSPARENT` 实现跨进程穿透；交互窗口通过 `SetWindowRgn` 限制为可交互区域，并与当前外壳求交。命中区域和绘制使用相同的动画尺寸、DPI、内容缩放、上下圆角。待机保留拖动与长按，音乐保留横条点击和内部控件。

命中缓存以整数像素边界为键，稳定帧不重复创建 HRGN。画布保留本显示器内已分配的最大尺寸，动画只更新几何，不逐帧重建交换链。DirectWrite 布局缓存、背景音乐/歌词/通知任务沿用现有实现。硬件初始化失败时自动转入 Direct2D 软件渲染；遵循系统减少动画设置。

## 运行依赖

Windows 10 1809+ x64。主程序采用 C++20 / Win32 / DirectComposition / Direct2D / DirectWrite，静态链接 VC 运行库。

top-docked 目录内保留 `lyric-provider` 和 `licenses`：歌词辅助 EXE、Qt6Core/Qt6Network、Schannel TLS 插件、VC DLL、qt.conf 及许可证。QCloudMusicApi/Crypto++ 链接在歌词辅助程序中。本次复用已编译的歌词组件，未更换歌词 API，不添加 Node/Python 产品运行依赖。Python 仅用于开发验证脚本。

## 验证范围与限制

环境：Windows 11 Pro build 26100、Intel Xeon E5-2666 v3、20 逻辑处理器、AMD Radeon RX 5700 XT、1920×1080，同时安装多个远程显示驱动。

四档 DPI 测试是程序诊断覆盖 100%/125%/150%/200%，实际创建渲染目标和 Windows 命中区域，**不是修改 Windows 全局缩放的实测**。音乐和消息回归输入均明确为合成数据，不代表真实播放器或 QQ 的端到端验证。

贴顶初版 r2 验证：原生自测 63 项通过；硬件路径 72 组布局通过（3 倍率 × 4 DPI × 6 状态），包含贴顶位置、平直上沿、圆角、文字/竖条边界、音乐下方消息、按钮中心命中、外部透明点穿透及快速展开/收回后完成动画。像素命中比较以 2 像素网格采样，无透明拦截命中。该硬件轮次之后仅修正 Windows 版本资源，没有改变布局代码；修正后重新编译并再次通过原生自测。

截图 `tests/top-docked-final-preview.png` 来自贴顶初版程序渲染，灰底仅用于让透明边缘可见；r3 缩小效果另见 `tests/top-compact-r3`。

重新编译后的软件渲染也通过同样 72 组检查，结果在 `tests/top-software-final-r2/results.json`。硬件结果在 `tests/top-layout-final-r2/results.json`。

最终 r3（消息 80%、待机高度 90%）验证：原生自测 64 项通过，包含新增性能 CSV 导出。默认 1.5 倍在四档程序 DPI 下，硬件和软件各 24 组布局回归通过。每组与 r2 实测尺寸直接比较，断言消息宽高为 80%、音乐部分高度不变、待机高度为 90%，并检查透明命中及音乐/竖条边界。结果在 `tests/top-compact-r3/results.json` 和 `tests/top-compact-software-r3/results.json`；新效果拼图为 `tests/top-compact-r3-preview.png`。

设置回归 `tests/top-settings-final-r2/results.json`：四档程序 DPI 下布局控件可见、矩形不重叠、滚动底部可达；播放器与歌词 API 不重叠；非法输入拒绝；独立倍率应用；恢复默认；关闭重开及进程重启保留 1.75 倍。连续 60 次分类切换，GDI/USER 对象由 `[36,119]` 到 `[37,116]`，没有明显累积。此项由诊断命令调用真实设置处理函数，不代替人工滚轮、Tab 和系统缩放测试。

控件回归 `tests/top-controls-final-r2/results.json`：四档程序 DPI 下，合成 SMTC 会话的上一首/播放暂停/下一首中心均在 Windows 命中区域内，FPS/Ping 同开时歌曲文字和竖条不重叠。本项没有点击真实播放器按钮。

性能基线使用更新前 `release/1.2.5alpha/WinIsland-1.2.5alpha.exe`（`1.2.5alpha-capsule95-20260907-r2`）。在同一性能序列里进程发生访问冲突退出，返回 `-1073741819`，测试端正在发送 `close-settings`。这只能说明基线采样中断，未定位崩溃栈，不能归因于这个命令。之前的“单实例锁”推测未获证实。因此本次没有可用的完整前后 CPU/帧耗时比较，不宣称降低了多少占用。性能脚本增加新目录检查和退出码检查，避免把已退出进程报告成界面阻塞。

进一步采样发现 CSV 最后一项出现乱码/重复名称；源码证实 `MetricCount=10`，但 `Perf::flush()` 的名称数组只有 9 项，造成确定的数组越界读取。已补上 `AccessibilityWork`，为 CSV 和中文报告名称表增加 `static_assert`，另加一个真实 CSV 导出回归。此问题发生在启用性能 CSV 采样时；中文监测报告原来的名称表有完整 10 项。该缺陷足以导致访问冲突，但没有旧进程崩溃栈，仍不能断言它是旧进程退出的唯一原因。

尚未验证：Windows 10、真实多显示器/竖屏热插拔、真实系统 DPI 切换、顶部任务栏组合、长时间运行、真实桌面拖动与播放器控制端到端、本轮真实 QQ 消息及汽水/网易云最小化歌词。本次调整外形不会补齐播放器没有上报的真实播放进度，保留既有静态歌词回退限制。独占全屏应用可能覆盖桌面置顶窗口。

## 最终构建采样结果

`tests/top-compact-extremes-r3/results.json`：1.0 和 2.0 倍在 100% 程序 DPI 下共 12 组检查通过。`tests/top-controls-r3/results.json`：四档程序 DPI 下音乐控制命中和 FPS/Ping 同开布局再次通过。最终缩小版本共执行 60 组布局截图检查（硬件 36、软件 24）。

`tests/top-perf-r3/metrics/latest.csv`：约 44.9 秒的合成音乐、4000 行歌词测量、反复展开/收回、连续通知及暂停/恢复序列完成；UI 工作和布局峰值均低于测试预算 50 ms，后台歌词测量只有一次。没有访问冲突退出，CSV 十项名称正确。

| 项目 | 本机本次实测 |
|---|---:|
| 进程创建至诊断 ready | 659 ms |
| 绘制提交均值 / 峰值 | 0.799 / 25.376 ms |
| 活动帧回调间隔均值 / 峰值 | 16.949 / 49.760 ms |
| 音乐状态应用峰值 | 7.773 ms |
| 容器布局峰值 | 0.440 ms |
| 后台 4000 行歌词测量 | 4.318 ms，一次 |
| 最终工作集 / 私有内存 | 68.08 / 46.11 MB |
| 全程 CPU 时间 | 7.891 s / 44.913 s，约单核 17.57%，20 线程全机归一化 0.88% |

帧回调间隔不等于显示器实际呈现 FPS。仍有约 50 ms 的间隔峰值，不能承诺没有掉帧。采样包含每 100 ms 的诊断 IPC（均值约 4.88 ms），正式模式不运行这套测试 IPC。未采集可信 GPU 占用数据，45 秒采样也不能代替长时间稳定性测试。

主 EXE 由更新前 1,109,504 字节变为 1,137,664 字节；增加 28,160 字节。本次未删减歌词依赖以追求体积。发布目录的 `build-manifest.json` 记录源码和 EXE/DLL SHA256，可核对实际运行版本。正在使用的旧构建目录没有被强行替换或终止。
