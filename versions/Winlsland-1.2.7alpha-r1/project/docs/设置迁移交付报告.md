# 1.2.7alpha Electron 设置替换：交付与验证

> 后续设置动画及双向切换、开关局部更新已另行交付，见 [设置动画优化与双向闪烁修复报告](设置动画优化与双向闪烁修复报告.md)。本文件保留迁移阶段的历史结果；其中“无设置动画”的描述不再表示当前 Electron 界面。C++、协议和插件 ABI 继续不变。

本报告取代此前“仅扩展少数字段 IPC”的结论。现在正式入口实际运行已打包的 Electron 设置程序，五个分类与插件管理由 TypeScript/HTML/CSS 实现。C++ 保留功能核心和唯一设置状态。

状态：**功能实现与当前单显示器环境验证已交付；尚不能称所有硬件环境的一比一验收完成。**

## 启动

运行本目录上一级 `release/WinIsland-1.2.7alpha.exe`（准确路径见 verification/release-hashes.json）。
必须保留同级 `settings` 文件夹，里面是已打包的 Electron 运行时；用户不需要安装 Node 或执行 npm。
从托盘“设置”或灵动岛右键打开设置。关闭设置不退出核心。
首次使用仍沿用基准的组件安装引导；此次没有重写安装器。旧的 build/build2/build3 和根目录旧 EXE 保留作为历史材料，不是此次交付入口。
主程序构建标识：`1.2.7alpha-electron-settings-20260914`；产品版本 `1.2.7alpha`，npm 版本 `1.2.7-alpha`。插件生命周期和场景 ABI 未修改。

## 已定位并修复的原因

1. 原 Electron 只有“桥接不可用”静态 HTML，没有表单、依赖构建和主程序入口替换。已替换为完整页面、preload、main 和可运行打包产物。
2. 原管道在后台直接修改 App 设置/窗口，范围错误，退出时会卡在 ConnectNamedPipe。现在线程分工明确，过期保存检查 revision，可打断管道等待。
3. 原管道只覆盖少量字段，成功不返回生效值。现在覆盖原版全部 19 个持久化字段，非法类型/范围拒绝，原子保存成功后返回实际快照。
4. 初次联调复现响应尚未消费就断开以及管道重建竞争。现使用同一服务句柄、长度帧、客户端读取确认、忙连接重试，并在超时和取消时释放 socket。
5. 插件不能以入队当作成功。增加操作编号、完成编号和独立错误；页面等到宿主完成，校验最终启用状态。
6. 实际截图发现表单按钮竖排和滚动导航遮挡内容。已改为按钮不收缩、固定导航、独立内容滚动，截图和 UI 用例已复核。

## 尚未验证的环境与限制

- 未完成物理多显示器拔插/跨屏 DPI、Windows 系统级动态效果开关切换和屏幕阅读器全流程验证。
- 未在此次会话重新实测在线音乐服务、真实十二段音频、QQ/系统通知业务。它们仍由原 C++ 模块提供；表单实际值与共享 configure/applySettings 调用已验证，不能据此宣称所有外部业务实测通过。
- 首次组件安装、离线盘、系统权限/自启动的全部组合不是此次 UI 替换验收范围，沿用旧实现。诊断运行使用独立目录绕过正式安装记录。
- 无有效媒体会话时，歌词按钮明确禁用；市场入口明确未开放；降低动画跟随系统，均不伪造能力。

- 设置文件为小型原子写入，在窗口线程确认提交；不承诺异常慢磁盘的绝对零阻塞。
- 旧原生设置仍编译供明确诊断使用，不是正式设置入口。旧历史 EXE 不具备新 Electron UI，必须运行 release 中的成品。
