WinIsland 1.3.2alpha 社区版
构建标识：1.3.2alpha-open-runtime-20260918
文档日期：2026-09-18；以本目录源码、SDK 和验证报告为准。

宿主管理任务为优先路径
startJob 只在 loader 回调创建。WiJobDefinition 的 work/context/done 一直有效至任务结束；host 保存定义。
work 在宿主创建的 MTA 后台线程执行，不能调用旧 scene/settings/media/add API。使用 WiJobContext.cancelled/progress/result，或本 owner 的 community.invoke(CONCURRENT)/publish/path。
每 owner 最多 8 个任务，全局最多 64；本版为有界任务线程，不承诺线程池复用或优先级调度。
result 复制最多 1MiB；progress 为 0..1000；done 在 loader 上收到借用的已复制数据，返回后不可保留指针。
jobInfo 返回运行1、取消请求2、已完成待回送3。回送并 join 后任务句柄回收，返回 NOT_FOUND；长期结果请在 done 保存到插件数据。
cancelJob 是请求；work 必须轮询 cancelled。正常主动取消可回送 CANCELLED；owner 停止后抑制 done，不会进入卸载后的 DLL。
完成标志之后宿主仍 join 工作线程，确认线程和线程局部清理均退出，才允许释放插件。

第三方库自建线程
允许，但必须在启动前 manageLifetime。stop 是非阻塞停止请求，只运行一次；joined 在 loader 轮询。
joined 只能在库已完成 join、所有回调和辅助资源确实停止时返回1。仅收到取消、设置标志、线程准备退出都不够。
外部线程不得直接调用社区/旧SDK的loader-only入口；已登记生命周期的线程可使用open中明确any-thread的方法，其他数据先入自己的同步队列，再由loader/受管理job接收。
open视图提供独立宿主STA，CREATE/LAYOUT/INPUT/DESTROY等回调在该线程；它不是任意主UI线程调用器。异步回调停止后使用viewBarrier屏障再确认joined。
辅助进程优先open.startProcess：宿主管理Job、私有IPC、合作停止与超时结束；进程和管道线程实际退出才释放owner。用户不需另行启动常驻应用。

退出次序与诚实状态
停止接受 owner 新工作与服务引用 -> 服务通知 STOPPING -> cancel jobs、停止外部库、抑制事件/完成 -> 释放本 owner 引用及可见修改层 -> 等待 active=0、所有 job join、external joined -> onDisable -> 撤销注册 -> onUnload/destroy -> FreeLibrary。
不能在 onDisable 才指望取消正在运行的 job，因为 onDisable 已安排在安全排空之后；使用 job.cancelled 或 lifetime.stop。
托管资源提前从屏幕撤销不表示 DLL 已卸载。UI 使用 loaded/stopping/pendingRestart 如实显示。
生命周期回调、LOADER 服务和事件回调必须短小；5秒初始化期限无法打断阻塞在 onEnable 内的同步原生代码。
错误 owner/错误线程/失效引用返回负数，不吞掉失败当作成功。
业务任务不会因为“降低动画”而停止，未改动任何动画参数。

本次扩展
新open owner自动注册外部生命周期，等待所有视图DESTROY和进程/pipe worker退出。停止超过5秒标pendingRestart仍保留DLL；真实排空后方可释放。本版open-lifecycle真实std::thread延迟退出示例已验证，并实际测试了WebView2异步回调/控制器关闭。永久卡死本进程线程不能保证安全热卸载；不做强杀。

STA异步回调屏障
viewBarrier在宿主视图STA回调内取得ticket，必须先取得ticket再发布pending=0/destroyed。外部lifetime.joined同时检查viewBarrierReady(ticket)==OK，表示该STA分发批次已经真正返回，覆盖回调尾声仍在执行的窗口。它不能取消未来回调；先关闭控制器、移除事件并追踪所有pending。普通外部线程仍需实际join。宿主内建lifetime不占用旧community供插件使用的16个名额。
