WinIsland 1.3.2alpha 社区版
构建标识：1.3.2alpha-open-runtime-20260918
文档日期：2026-09-18；以本目录源码、SDK 和验证报告为准。

三个层次必须区分
1. 宿主接口：queryInterface 返回 scene/settings/media/community 等宿主表。
2. 社区服务：registerService 将模组能力注册在 community 内；queryInterface 不返回第三方裸表。
3. 宿主实际扩展点：图片/流式解码进入媒体流程；open v1 的视图、文件、进程、业务替换接入各自实际流程。一般服务仍不会自动进入未接通的私有逻辑。

服务标识及 ABI
使用命名空间字符串，例如 org.example.browser.view，最长 159 字节，ASCII 字母数字 . _ -，必须含点。
provider 由宿主当前 owner 填入，注册参数没有 provider 字段。
WiServiceTable 是通用方法分发头：size/version/context/invoke，宿主复制这个头；context 必须活到安全停止。
interfaceVersion 是该服务自己的契约版本，与分发头 version=1、模组 version、产品版本各自独立。
interfaceSize 是宿主支持并复制的分发表大小 sizeof(WiServiceTable)，不意味着任意扩展尾部已支持。
方法参数使用约定的 POD/字节缓冲。不得传 STL、跨 CRT 释放指针或让异常跨 DLL。每种社区服务应另附自己的方法号、参数结构 size/version、编码与错误规范。

注册和发现
registerService 返回单调递增句柄，初始 REGISTERED。初始化完成后显式 setServiceState(READY)。初始化失败可标 FAILED 并返回失败。
清单 providesServices 是启动宣告；宿主会等待所有宣告接口 READY，最多 5 秒。在这段时间 pump 后台完成和服务事件；不要阻塞 onEnable 本身。
没有宣告的运行时服务也能注册，但不会被清单预启动；消费者需运行期发现。
订阅 service.changed，payload 是按字节复制的 WiServiceInfo，含状态与接口/提供者。回调只借用数据，不保存指针。以 enumerate 为当前真值；历史事件不保证服务仍可用。
服务状态序列 REGISTERED -> READY -> STOPPING/FAILED -> REMOVED。停止不能原地变 READY，需注销并重新注册，新句柄代表新代次。

查询与引用
enumerate 给总数量，容量不足返回 LIMIT；可先 capacity=0 获得数量，再申请缓冲。
acquire 按 id、可选 provider、闭区间 minVersion/maxVersion、requiredCapabilities 筛选 READY 服务。
默认选择接口版本高者，再按 provider ID ASCII 字典序；同 provider 的重复 id+version 拒绝。不得以加载先后猜测。
acquire 返回引用句柄并可复制 WiServiceInfo。句柄与消费者 owner 绑定；不会随新提供者出现自动改指向。
invoke 经宿主门禁与 active 计数调用，函数执行结束才减计数。LOADER 服务只能在 loader 调用；CONCURRENT 可在已登记宿主任务/媒体线程调用，提供者必须保证线程安全。最多 16 层嵌套。
同步 invoke 返回本次结果；它不是自动异步 RPC。耗时服务可在消费者 startJob 内 invoke(CONCURRENT)，或自己定义 requestId + 事件/查询结果协议。注册任务不等于结果已经完成。
release 释放当前消费者引用；一个消费者释放不销毁其他引用。停止消费者时自动撤销其全部引用。
unregisterService 先置 STOPPING，拒绝新调用；仍有引用或活动调用返回 BUSY，需等真正退出/释放后重试。

服务依赖清单
serviceDependencies: [{"id":"org.example.compute","minVersion":1,"maxVersion":2,"provider":"my-base","optional":false}]
必需依赖：根据已安装且清单有效的 providesServices 选择最高兼容版本，再按 provider ID 排序；DFS 启动真实提供者，检测循环；提供者就绪后才调用消费者 DLL。
启动恢复不擅自启用上次禁用的提供者；依赖被禁用时消费者标记无法恢复并说明服务名。
optional=true：不预启用任何提供者，不阻止消费者，使用 acquire 的诊断结果决定降级；运行时可监听 service.changed。
有多个提供者且要求稳定选择时，在依赖和 acquire 都显式填写 provider。新增 READY 服务不会替换已获取引用。

关闭关系
真实必需依赖和已取得的服务引用共同形成关闭关系。关闭提供者时存在活跃消费者，默认阻止；确认连带关闭才按消费者在前的顺序处理。
循环运行时引用也会去重并关闭整个相关闭包；不依赖纯拓扑图才安全，门禁先停止，调用/任务排空后才卸载。
消费者中的后台调用已经进入服务时，不释放提供者 DLL。未进入的调用在 STOPPING 后返回 STOPPED。
服务故障返回诊断错误，社区回调异常被记录并触发相关 owner 关闭；普通返回码失败由消费者处理/降级。异常捕获不是内存破坏隔离。
