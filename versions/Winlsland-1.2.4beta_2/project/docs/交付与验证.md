# 1.2.4beta_2：歌词后端与后台数据检测

这是此前歌词构建的历史验证记录。当前最新外形构建为 `1.2.4beta_2-capsule95-20260907-r2`，新增变化与验证见 [外形与尺寸95验证](外形与尺寸95验证.md)；本文件原有歌词结果及限制保持有效。

2026-09-07；BuildId：`1.2.4beta_2-qcloud-20260907-r1`。

**已完成新版本代码与可运行目录构建，但网易云最小化后的连续歌词同步仍未通过真实测试，不应将此版称作问题已彻底修复。**

## 本次确认的原因

1. 本机网易云 `D:\CloudMusic\cloudmusic.exe`，版本 **3.1.39.205426 x64**。SMTC 能取得歌名、歌手、播放状态和控制能力，却没有提供有效专辑／时长／播放时间轴。前台可通过 MSAA/IAccessible2 取得经过歌词正文校验的当前行；最小化后该行冻结。本次观察中没有得到可以持续同步的后台进度。
2. 旧代码遇到最小化／不可见窗口直接跳过辅助功能读取，即使某些客户端版本仍更新后台当前行也无法使用。新代码取消了这个无条件过滤，改为核验当前行是否实际发生变化。冻结快照不能通过每轮读取续期；切歌清除，后台更新停止后 2–15 秒内失效。此修正不意味着本机网易云会开始提供它原本没有的数据。
3. 歌词服务与播放器窗口没有依赖关系。真实 QCloudMusicApi 普通／新版接口在窗口显示和最小化时都能返回、解析同一歌曲歌词。接口只返回正文及其时间标签，不能提供本机当前播放位置。
4. 本轮另有真实匹配失败：`与我无关`、`只不过是`存在多个符合歌名和歌手的录音候选，而播放器缺少专辑／时长；`雨水`未通过元数据匹配。日志分别记录 `ambiguous_recording`、`metadata_or_version_mismatch`，没有归为网络故障。未放宽到直接选第一个结果。
5. 已排除先前怀疑的 BetterNCM：当前 x64 网易云没有加载旧 x86 插件残留；不能将时间轴全零归责于该插件。没有安装、注入或修改播放器插件环境。

## 数据源顺序与限制

默认顺序不变：本地导入／校验缓存 → LRCLIB 精确 → 网易云搜索确认 ID＋普通歌词 → 网易云新版 → LRCLIB 搜索。只有自动模式跨曲库降级；指定源遵守用户选择。

新增 `LyricSource=5`：网易云搜索仍用原生 WinHTTP；歌曲匹配后由 QCloudMusicApi 取得歌词正文。自动模式遇到网易云歌词的 WinHTTP 传输错误时可以尝试该后端，不绕过 HTTP/API 限流和拒绝。它是相同网易云上游的另一种传输封装，不能视为独立曲库。

未加入第三方代理／HTML 抓取。这些方案没有解决本地进度丢失，还会额外引入上游、凭据或页面结构依赖。网易云接口属于非公开接口，没有稳定性承诺。新版可能返回 LRC 或 YRC；逐字数据按行显示，不宣称逐字高亮。

## 性能与发布

新歌词后端只在请求期间存在；主界面没有 Qt 依赖。子进程最大 7 秒／1 MB，旧请求可取消，歌词 worker 最多两次尝试，退避沿用原实现。启动与动画不等待网络。后台当前行读取仍在现有媒体 worker 中。

不能声称换库提高了性能。一次真实观察的渲染提交平均约 0.65 ms、最大 12.20 ms，活动帧回调最大约 281 ms（包含设置打开和诊断 IPC）；缺少相同条件下的前后性能对照，且没有独立 GPU 测量。完整原始采样保留于测试目录，不作为“所有环境流畅”的证明。

运行目录：`release/1.2.4beta_2/`。必须保留 `lyric-provider`。Qt6Core、Qt6Network、Schannel 插件、所需 MSVC DLL 已随包部署；主程序静态 CRT。最低 Windows 10 1809 x64，系统提供 UCRT／SMTC／Schannel／DirectX。无需 Python、Node、开发环境或单独安装 Qt。
