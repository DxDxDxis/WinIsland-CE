# 1.3.0 目录、插件状态与插件页面转场修复

构建标识：`1.3.0-path-state-fix-20260916`。产品仍为 1.3.0 社区版，插件 POD C ABI 仍是 0x00010002；场景/媒体/设置接口版本均未变化。

## 实际原因

旧安装器只释放歌词组件。`dataDir()` 固定返回 LocalAppData，插件包取 EXE 同级 mods，设置进程取 EXE 同级 settings，Electron 又使用 Roaming AppData。安装取消返回值还被忽略。缺少统一根目录使这些文件散落在多个位置。

扫描把未知、缺失甚至损坏的 host-state 当作 enabled；恢复依赖时递归 enable 不检查依赖的已保存选择。退出和重载也经过写入 unloaded 的 disable，再恢复原值，中间异常退出会改变用户选择。

原转场在开场移除设置 DOM，返回时又把设置 visibility 设为 hidden。因此面板下方先变空。原时长为 540ms；速度降到 90% 后是 600ms，并非 486ms。

## 目录结构

```text
用户确认的根目录/
  components/runtime/<清单 SHA256 或独立修复目录>/
    settings/             Electron、asar、资源及运行依赖
    lyric-provider/       Helper、Qt、MSVC DLL、qt.conf、tls
    licenses/             原工程携带的第三方说明
    component-manifest.json
  mods/                   .wimod 包
    <稳定插件 ID>/        host-state.txt、settings.xml、mod.log、quarantine.txt
  mod-cache/              解压、资源、重装隔离缓存
  settings.xml            主程序设置及布局
  lyrics/                 歌词与歌词服务缓存
  electron-data/          Electron userData/sessionData 与子进程本地/漫游缓存
  logs/                   安装、诊断、Electron、可选性能记录
  monitor/                现有监测快照
  temp/                   主程序/运行库可控制的临时文件
  migration/              迁移标记、冲突副本、原安装记录备份
  .component-staging/     发布前的独立暂存目录
  install-state.json      实例、组件集合、当前清单、受管理文件
```

固定引导记录仍是 `%LOCALAPPDATA%/WinIsland/installer/install-location.json`。只读系统通知数据库依然属于 Windows；不能将其改到应用根目录。用户主动导出的文件和显式诊断测试输出按用户/测试指定位置处理。

所有正常运行路径显式使用 dataDir。没有通过修改全局工作目录掩盖路径来源。歌词子进程保持组件目录作为工作目录；Electron 的工作目录是数据根目录。它们的 APPDATA、LOCALAPPDATA、TEMP/TMP 也显式指向根目录下的运行缓存。Windows 自身的预读取、事件日志、WER、杀毒缓存等不由应用控制，不承诺将这些系统文件迁入应用目录。

## 定位、释放和修复

定位协议 format=2，保留读取旧 format=1 的兼容逻辑，包括旧 writer 未转义 Windows 反斜杠的特定格式。未知协议版本停止写入。损坏字段、实例不匹配、目录删除/离线和不可写会显示恢复路径入口，不能按“新用户”静默建立空数据。

磁盘候选只查询固定盘、剩余空间和候选祖先目录写权限，不扫描磁盘；不在用户确认前创建 WinIsland 目录。建议预留为解压文件大小的两倍加 256MiB。手选路径不自动换盘。

组件标识是确定性文件清单的 SHA256，与产品显示版本分离。每次启动对当前所需组件检查文件大小、SHA256 和额外文件，完整校验约 377MiB 的运行文件；这是可靠性取舍，有真实启动成本，不宣称零开销。无变化时不解压、不改定位记录。

安装操作有固定定位锁和目标根目录锁。发布前在唯一暂存目录释放并校验；发布目录从不覆盖已加载文件。损坏组件修复到另一个目录，原目录保留。进程启动后固定自己的组件路径。切换已存在的另一套组件仍提交活动记录；不能只改进程内路径而留下旧记录。

解压失败/安全阶段取消不提交新记录，旧数据与组件保留；进入提交阶段禁用取消。记录通过唯一临时文件、FlushFileBuffers 和替换提交。中断留下的暂存目录不会作为已安装组件使用。旧版本组件和中断暂存目录暂不自动清理，以避免误删仍在使用的文件；需要额外磁盘空间。

## 迁移与冲突

只读取已知 LocalAppData/WinIsland、EXE 同级的 mods、mod-cache、lyrics、monitor、logs、settings.xml、旧 daxian日志，以及旧 Roaming/WinIsland/settings-ui。测试模式把这些来源全部重定向到隔离目录。

迁移先复制到唯一临时文件，校验大小/SHA256，再提交目标；源文件不删除。目标已有不同内容时保留目标，源副本进入 migration/conflicts，并记录具体源路径。相同插件 ID 的不同包放入冲突区，不同时放进 mods；同内容跳过。安装窗口对冲突给出提示并等待用户启动。

每个来源完成后记录迁移标记；后续修复或升级不会重新导入用户已经移除的旧包。重试只处理尚未完成的来源。普通启动不会重新扫描这些来源；插件扫描只扫描根目录 mods 中的包。

## 插件状态

- 保留原 `mods/<ID>/host-state.txt` 格式：enabled / disabled / unloaded，包改名或缓存哈希变化不改变身份。
- 新导入继续默认禁用；未知或损坏状态保持禁用，并记录原因。
- 用户禁用/卸载先原子保存意图，然后释放资源；启用成功保存选择。正常退出不再写意图文件，重装和临时清理也不改意图。
- 启动恢复只递归恢复已保存 enabled 的依赖；依赖被禁用、卸载或无法兼容时，显示具体恢复失败原因，不自动开启无关插件。
- 用户明确点击启用仍按原语义处理真实依赖。批量禁用覆盖已扫描条目的选择，但保留原有清单/ABI/依赖错误诊断。
- 回调故障写 quarantine.txt，释放资源而不伪装成用户禁用；下次不自动重试。用户明确启用成功后清除隔离记录。
- 卸载沿用当前产品语义：停止并卸载 DLL，保留包和配置；unloaded 使下次不自动启用。手工移除包也不会由迁移重新安装。

## 转场与输入

只有一套活动转场。真实设置 DOM、表单草稿、布局和 main 滚动位置始终保留在下层；inert 暂停输入。插件有独立滚动视口，背景面板在上层从真实按钮矩形展开，内容以裁剪和透明度显现，文字不缩放。

打开/返回均从 540ms 改为 600ms，曲线保持 cubic-bezier(.2,.75,.25,1)。反向和窗口变化先读取实际合成矩形，再取消旧动画并衔接最新目标。序号阻止旧 finished 回调提交状态。返回前读取真实核心值，仅同步核心发生变化的字段，保留未提交草稿；底层页面不会先变空。

结束时恢复焦点、输入、自然视口状态并移除临时背景；返回后插件节点脱离文档，不能接收输入。窗口关闭取消动画并解除观察器。减少动态效果时直接完成终态。主导航弹簧、卡片展开、灵动岛动画和插件动画系统保持原有行为。

## 回退

原始 1.3.0 与 r1 完整目录保留，SHA256 核对结果见 verification。关闭新进程再运行原 EXE；原路径数据没有删除。旧程序未集成本次统一目录协议，不能宣称它会自动复用新根目录或新状态。

迁移时的原定位记录/安装状态备份在新根目录 migration/original-install-location.json 和 original-install-state.json（仅当旧记录存在）。如回退至旧程序且需要旧组件定位，先保留当前记录，再将该备份恢复到固定定位文件；不要清空新根目录或复制覆盖用户插件设置。新机制兼容 EXE 间按所需组件切换，与未修改过的历史 EXE 自动升级能力是两回事。

新增测试：settings-electron/verify-repair.cjs、verification/verify-installed-runtime.cjs、主程序 --storage-test。--verify-installed 显式使用隔离引导/旧来源目录并启用已有诊断接口，只用于测试，不用于用户日常启动。
