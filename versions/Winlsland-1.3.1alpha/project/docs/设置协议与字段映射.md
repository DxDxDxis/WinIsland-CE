## 状态与线程

HTML/TypeScript renderer → 隔离 preload → Electron main → 命名管道 → C++ 窗口线程。
管道线程只做有界读写；通过 `SettingsRequestMessage` 通知窗口线程处理。设置仍保存在原版 `settings.xml`，没有 Electron 设置副本。
小型配置文件原子写入成功后，C++ 发布新 revision，调用原版 position/applySettings，返回完整实际值。后台旧保存任务会核对 revision，不能把后来生效的值覆盖回去。
插件操作由原 ModLoader 工作者执行；操作编号、完成编号和错误独立发布，不能把“已排队”显示为“已完成”。

## 协议

- 命名管道：`\\.\pipe\WinIsland.Settings.<PID>`，仅当前用户 DACL、拒绝远程客户端。
- 每连接一请求；4 字节小端长度 + UTF-8 JSON。请求上限 64 KiB，响应上限 4 MiB。
- 请求：`{protocol:1, token, command, params}`。随机 token 由 C++ 传给本次 Electron 进程，renderer 不接触它。
- 响应包含 `ok`；失败包含 `code/error`。客户端读取完响应后发送确认字节，再断开连接。
- Electron 请求超时 8 秒；管道单次 I/O 超时 5 秒，可用停止事件打断。UI 可取消等待。已经被宿主接受的插件操作不因取消等待而强制中断，刷新取得真实结果。
- main 只接收当前主 frame 的白名单命令，串行调度，最多 32 个待处理请求；文件路径由 main 文件选择器注入。
- 设置提交携带 revision，冲突返回 CONFLICT。非法输入返回 INVALID，renderer 恢复最后确认值。
- diagnostics 下才生成 `settings-connection.json` 供验证，正式运行不写此文件。它包含测试会话令牌，不随发布目录交付。

## 界面与权限边界

固定导航和独立内容滚动，所有页面同步设置 hidden/选中状态，无 CSS transition、animation、关键帧或 GSAP 页面调用。插件页返回恢复原分类、滚动和焦点。
所有表单来自 typed protocol；原生 label/input/select/button、键盘 tablist、可见焦点、aria-busy、错误关联。静态 hover/focus 颜色保留。
Electron contextIsolation=true、nodeIntegration=false、sandbox=true；CSP 阻止网络、内联脚本和表单导航；拒绝新窗口、页面导航及权限请求。renderer 没有文件系统或进程 API。
核心窗口、媒体/通知/歌词业务、原 C ABI、QuickJS/GSAP/miniz 和组件安装机制保持。没有新增 Rust 插件，也没有更改时间显示插件。
