# WinIsland 1.2.3beta 交付与验证

本次交付为 C++20 原生实现，窗口、渲染、动画、音乐、通知、托盘、设置和后台任务均已迁入 C++；不依赖旧 C# 程序启动。原发布版本保留供对照和回退。功能自动验证与第三方播放器实机验证分开记录，下列未测项目不能视为通过。

## 设置与诊断

- 设置采用统一的圆角卡片、输入框、按钮、开关、文字和间距；保留原生编辑、键盘操作、焦点和禁用状态，窗口可滚动。
- “启动信息监测”切换为“停止信息监测”；每 5 秒后台采集 CPU、内存、句柄、GDI/USER 对象，记录关键模块耗时、状态变更和错误。
- “导出日志报告”在监测中导出快照，停止后导出完整会话。UTF-8 BOM 文本默认保存到 EXE 同目录的 `daxian日志/daxian日志_年月日_时分秒.txt`；同秒重名加序号。不可写时回退到当前用户“文档/daxian日志”，设置中显示可复制的实际路径。两处都失败时明确提示，内存记录保留。
- 最多保留 1024 条事件、720 次资源采样；累计耗时直方图覆盖本次会话，超限会注明被淘汰条数。当前和最近一次停止快照在 `%LOCALAPPDATA%/WinIsland/monitor`。重新监测会替换内存会话，需长期保存的报告请先导出。
- 正常监测报告不包含聊天正文、歌名、账号或凭据。开发用 `--verify` 状态文件包含测试内容，不属于面向用户的诊断报告，不应拿来采集私人会话。

## 已确认的问题及修改

| 原因/证据 | 修复 | 文件 |
|---|---|---|
| 旧 WPF 版在展开/收起时重复测量整份歌词；4000 行压力 LRC 触发 30 次测量，主线程平均 293.473 ms、峰值 385.690 ms，音乐回调间隔峰值 406.405 ms | LRC 解析、完整歌词测量和封面解码移到后台；缓存紧凑/展开宽度，界面只取结果；渲染使用缓存文本布局 | `src/core.cpp`、`media.cpp`、`render.cpp` |
| 原生移植初期 XmlLite 结束节点深度与开始节点不同，造成通知正文解析错误；UTF-8/UTF-16 测试复现 | 修正结束层级，解析只选择可见文本，排除按钮、归属文本和外部实体 | `src/notifications.cpp`、`tests.cpp` |
| 诊断测试程序占用 state.txt 时，原子替换失败触发模态错误框 | 仅测试快照失败跳过本次写入，下次重试；配置写入仍报告失败。此项是测试通道问题，不能认定为旧生产版卡顿根因 | `src/app.cpp`、`tests/verify-native.py` |
| 高刷新率显示存在小数刷新率，整数调度会产生周期偏差 | 使用 DWM 的有理数刷新率；低资源/软件路径默认 60，手动帧率仍有效；非阻塞提交遇到忙时重试 | `src/app.cpp`、`render.cpp` |
| Windows 原生文件选择框、托盘菜单有独立模态消息循环，常规等待计时器不被外层循环处理 | 模态期间使用临时窗口计时器继续动画，关闭立即撤销；恢复原控制悬停提示，键盘焦点独立保留 | `src/app.cpp`、`accessibility.cpp`、`render.h` |
| 隐藏控件可能仍残留键盘焦点 | 所有控制入口重新检查当前曲目、展开状态、忙状态和真实能力，避免向已隐藏的操作发命令 | `src/app.cpp` |

音乐/通知/音频由独立工作线程采集，UI 消息循环只消费快照；媒体订阅在会话替换、退出时移除；串行后台任务在销毁依赖前排空。通知采用只读数据库、启动基线、身份与内容去重、FIFO 和更新合并。同一容器向下展开消息，收起保留已展开音乐状态。没有调整进程优先级。

**尚未确认：**用户日常短歌词下的全部卡顿原因、显卡驱动/远程显示驱动/电源策略的贡献、所有硬件上的实际呈现掉帧情况。本机有多个虚拟显示驱动，不据此推断驱动就是根因。

## 测试范围

实际主机：Windows 11 x64 build 26100，Intel Xeon E5-2666 v3（20 逻辑处理器），AMD Radeon RX 5700 XT，并安装有远程/虚拟显示驱动。硬件和强制软件渲染是在同一台主机测试，不能代替不同性能档电脑实测。

| 项目 | 结果与边界 |
|---|---|
| 12 项原生自测 | 通过：配置与歌词哈希兼容、LRC 时间/空行、动画函数、平台过滤、时间轴、通知 XML |
| 硬件渲染集成 | 通过（tests/hardware-release3）：尺寸、展开/收起、通知反向动画、12 条排队、反复打断、设置保存、日志、真实 SMTC 与 PCM |
| 软件渲染集成 | 解压包通过（tests/software-release）同一核心流程及原生文件选择框动画时钟；此前测试与正在运行的普通窗口重叠时发生指针超时，隔离测试位置、加入动作确认后重测通过。不能将所有历史超时断言为生产缺陷均已解决 |
| 设置缩放 | 本机用 100%/125%/150%/200% 渲染比例验证边界、下方消息、滚动可达；并非在四种真实系统缩放和字体环境分别实测 |
| 日志路径异常 | 默认位置被同名文件阻挡时，成功回退到文档；同秒导出不覆盖。企业 ACL、网络重定向文档、磁盘全满未实测 |
| 真实 Windows 系统通知 | 通过（tests/system-toast2）：提交专用测试通知 → Windows 系统数据库 → 原生解析 → 灵动岛展示；测试后只删除该测试通知 |
| 音乐与消息同时出现 | 合成数据库通知 + 原生真实 SMTC 测试媒体通过；消息不折叠展开面板，队列和反向动画通过 |
| 多屏、锁屏、休眠、显卡设备热拔插 | 有对应处理代码，未完成实机组合验证 |
| Windows 10、低配办公机、无独显、无开发环境干净系统 | 未实际测试，不能由软件渲染通过推定全部兼容 |
| 多天运行 | 未验证；短时采样 140.94 秒后应用进入退出流程，触发源未确定，计划持续测试未完成，不能记为通过 |

## 音乐平台与 QQ 通知

| 平台 | 原生版实际测试 | 支持条件/限制 |
|---|---|---|
| 网易云音乐（本机已开启 SMTC） | 读到歌曲与真实封面；实际开始播放、点击原生面板暂停并回读成功，恢复原暂停状态；未切换用户歌曲 | 本机此版本没有 SMTC 时间轴、循环/随机能力，因此不显示同步歌词/模式入口。上一首/下一首声明支持，但未在该实际播放器点测 |
| QQ 音乐 | 尚未实测 | 按真实 SMTC 元数据和能力工作；需具体 Windows 客户端提供会话，不能保证所有版本 |
| 汽水音乐 | 尚未在原生版实测 | 同上；旧 C# 测试不能当作原生版通过证据 |
| 原生测试媒体 | 真实 Windows SMTC 上一首/下一首/暂停/恢复、时间轴 LRC、真实 PCM、静音回落、模式读写、忽略命令隐藏、暂停 10 秒及退出通过 | 测试媒体是专门的原生发生器，不能等同于以上三个商业客户端兼容性 |

歌词保留本地 LRC 导入/清除，只有播放器提供真实进度才能同步。六根竖条是所选进程真实 PCM 音量历史，不是随机动画或多频段频谱。账号收藏没有可靠 SMTC API；原版没有真实可用收藏、音量滑块或在线歌词，此次没有伪造这些能力。

QQ 消息的前台、后台、最小化、托盘、QQ 重启、多会话实机组合仍未验证。合成通知可验证接收后解析、去重、队列和展示；只有 QQ 向 Windows 发布系统通知时才可接收，前台会话/免打扰/关闭系统通知可能根本没有该事件。可行替代是启用 QQ 系统通知及 Windows 通知权限，使用后台/最小化场景验证。不能承诺读取 QQ 未发布的消息。

## 发布与依赖

`build.ps1` 用 MSVC x64 C++20、`/MT /O2 /Gy /Gw /OPT:REF /OPT:ICF` 构建。静态 VC/C++ 运行库、图标、应用清单和版本资源在 EXE 内；PE 检查 CLR 目录为零，无 .NET、Python、WebView2、Qt 或独立 VC 运行库依赖。只依赖支持系统提供的 Win32、Direct2D/DirectWrite/DirectComposition、WinRT、WASAPI、GDI+、XmlLite 等。winsqlite3 从 System32 动态加载，缺失时降级通知能力。

目标最低 Windows 10 1809 x64；建议 Windows 11。进程音频回环需 build 20348+，较旧系统保留媒体信息/受支持控制并使竖条保持基线。系统组件不从第三方下载，不要求用户强制升级应用；损坏/裁剪系统的系统 DLL 应通过 Windows 维护修复，不静默安装未经校验的 DLL。没有联网补依赖流程，因为可分发运行库已静态内置。

原 XML 设置和 SHA256 命名歌词继续使用 `%LOCALAPPDATA%/WinIsland`。正常启动保留单实例与原有开机启动项行为。用完测试版可以退出后运行原 EXE 回退。发布包不包含测试媒体、测试音频、编译工具或诊断测试文件。

## 复现与诊断

构建和运行命令见上一级 `README.md`。在卡顿电脑上打开设置，启动信息监测，复现音乐/消息/动画卡顿，再停止并导出报告。报告的“活动帧回调间隔”是 CPU 调度指标，不是显示器实测 FPS；渲染提交不包含全部 GPU 工作，当前未采集 GPU 占用百分比。不要据此宣称所有环境不卡顿。

最终性能数字、发布文件大小及压缩包检查结果见 `性能与发布数据.md`。
