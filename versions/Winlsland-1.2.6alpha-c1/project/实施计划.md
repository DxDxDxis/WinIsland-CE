# .wimod 实施计划

基础：复制已经构建和测试的 1.2.6alpha-c1-plugin-manager。原版不修改。本副本保留 1.2.6alpha-c1 版本号，并单独标识 wimod 构建。当前已完成单文件包扫描、校验、缓存解压、DLL 生命周期、管理 UI 与示例包验证。

1. 包与依赖：静态编译 miniz 3.1.0（MIT）读取 ZIP；包根 mod.json；拒绝路径穿越、重复路径、链接、加密/超限包；可选 Windows CMS 签名校验；内置缓存按内容哈希隔离；支持对象形式的版本依赖。
2. 加载器：扫描 EXE 旁 mods/*.wimod，清单与包错误仍进入真实列表；日志和配置留在 LocalAppData；按依赖加载，在后台提取 DLL；禁用/卸载不删除包或缓存。
3. 扩展接口：复用 POD C ABI 与 owner 资源登记，补音乐/通知/窗口/渲染等事件和可逆目标；停止人工限定三个替换项的设计；增加通用服务替换链、托管后台任务和取消/等待机制，逐一接入实际主程序。
4. 管理界面：改为导入 .wimod，显示文件名；列表顶部放添加、目录、刷新、市场与批量操作；保留已验证的详情、错误、默认字段和键盘/DPI 行为。
5. 样例与验证：编译和打包真实 ExampleMod.wimod，验证安装/载入/事件/按钮/设置/图层/恢复；恶意或损坏 ZIP、版本依赖、重复包、停止期间回调；最终构建与真实窗口测试。

音乐布局缩放修正：`MusicScale=0.9` 只在 App 几何阶段应用一次；Renderer 使用统一岛屿坐标，不再用 `1/MusicScale` 反向抵消，避免视觉上恢复原尺寸或放大。

同进程原生 DLL 不是进程隔离沙箱：不能承诺任意内存破坏或死循环后仍安全恢复。生命周期和 API 明确所有权，不跨 DLL 传递 STL，也不强杀线程。
