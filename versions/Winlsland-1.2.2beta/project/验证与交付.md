# 1.2.2beta：系统帧率与可配置帧率

日期：2026-09-06。显示版本为 `1.2.2beta`，程序集／文件版本为 `1.2.2.0`。

## 使用与行为

右键托盘 → 设置 → 动画帧率。默认值 `0`：普通环境跟随 Windows/WPF 渲染事件，不额外限制到 60 FPS；低性能判定（WPF Tier 0、CPU ≤2 或内存 <4GB）时默认目标为 60 FPS。手动填写 30–240 的整数后立即生效，优先于自动策略，重启保留。无效值保持当前帧率，并在输入框旁提示。

这里设置的是更新目标上限，不是保证实测帧率。屏幕、WPF 或硬件低于目标时不会人为补帧。跟随系统也不会把低于 60 Hz 的屏幕强制改成 60 Hz。

设置窗口增加高度，并在小工作区允许纵向滚动；说明文字换行，歌词按钮仍可访问。继续使用 `%LOCALAPPDATA%\WinIsland\settings.xml`，新增 `FrameRate` 元素；旧配置缺少该项时取 0，其他设置与歌词数据不变。

## 修改文件

| 文件 | 修改 |
| --- | --- |
| `Compatibility.cs` | 自动／手动帧率策略；按 WPF RenderingTime 去重；固定目标使用分数时间间隔和持续截止时间，避免整数毫秒截断与高刷误跳帧；卡顿后跳过过期帧而不积压补帧 |
| `IslandWindow.cs`、`MusicView.cs` | 外壳与六根真实音频竖条使用各自的帧调度器；竖条平滑按实际时间计算，切换帧率不改变回落节奏 |
| `Settings.cs`、`SettingsWindow.cs` | 帧率输入、校验、即时应用、持久化、旧配置兼容和窗口布局 |
| `Program.cs` | 诊断帧率、实际回调计数、设置截图和测试命令 |
| `AppVersion.cs`、`build.ps1` | 统一 1.2.2beta 显示与构建文件名 |
| `SelfTests.cs`、`verify-framerate.ps1` | 调度、持久化和可见设置界面的验证 |

## 本次实际验证

本机 Windows 11 Build 26100、WPF Tier 2、20 逻辑 CPU。记录在源码 `artifacts` 下。

| 验证 | 结果／证据 |
| --- | --- |
| 逻辑自测与回归 | 47 项通过，`fps-selftest.txt` |
| 设置界面、版本号、实时切换、无效输入、重启保存 | 通过，`fps-verify/verification.txt`（专用脚本共 12 项） |
| 强制低性能策略 | 实际运行通过；默认目标 60、手动 144 覆盖成功。这是在本机强制选择策略，不代表真实低端硬件测试 |
| 实际音乐回调计数 | 60 FPS 目标下约 55 次/秒（3 秒采样）；这是 UI 更新回调计数，不是 GPU 呈现帧率 |
| 音乐与消息同时展示、切换帧率途中展开／收回 | 通过，动画完成、消息仍在音乐下方 |
| Windows 通知、队列、设置、退出及辅助进程 | 常规 20 项回归通过，`fps-notifications/verification.txt` |
| 设置窗口视觉检查 | `fps-verify/settings.png`：帧率输入和歌词按钮完整可见 |
| 60／120／144／240 Hz 下固定帧率／跟随策略 | 模拟渲染时间戳测试通过；不表示在这些刷新率的物理屏幕上实测 |

尚未测试：多种真实高刷屏、朋友电脑、低端 CPU/GPU、不同 Windows 版本、多屏与混合 DPI、数小时运行。不能据本次结果宣称全部兼容或稳定达到设定帧率。

音乐平台接入、通知接收、真实音频来源和本地 LRC 同步协议没有改变。本轮没有重新测试三个音乐客户端或 QQ 所有真实收消息场景；此前网易云／汽水的控制测试与 QQ 音乐未实测的边界仍有效。

## 依赖及历史记录

本次没有新增外部运行库、网络下载、强制升级或配置迁移。EXE 使用系统 .NET Framework/WPF 和 Windows 接口。缺少 CLR 时应用自身无法启动检测或安装，请使用 Microsoft 官方组件；不要把“无需额外 DLL”理解为已嵌入操作系统运行库。
