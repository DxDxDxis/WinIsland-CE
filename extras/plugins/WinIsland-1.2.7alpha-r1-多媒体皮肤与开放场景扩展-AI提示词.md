> 需求理解：进一步提高灵动岛开放性，让插件制作图片、动图、视频皮肤，并自由组合功能组件，调整整体尺寸、布局和交互。原生设置界面继续由宿主管理。

## 1. 任务目标

请基于我提供的最新 WinIsland 社区版源码，开发 **1.2.7alpha-r1**。核心目标是建立完整的多媒体皮肤和开放场景能力，让第三方开发者通过插件自由添加、减少、隐藏、替换和修改灵动岛上的内容。

皮肤不仅是更换一张背景图，还应支持：整体外形与尺寸、背景和前景、图片和动图、视频、文字和图标、按钮和滑块、播放进度及其他功能组件。插件可以将这些内容自由组合，形成自己的灵动岛界面。

必须依赖主程序运行，继续通过主程序加载插件、调度资源和渲染；最终支持单个 `.wimod` 分发。普通用户无需手动摆放 DLL 和 JSON。

本次不要求重新设计原生设置页面，也不允许插件任意修改原生设置页面。插件可以在自己的设置页配置皮肤、媒体、布局和行为。保持已有无页面切换动画的要求；视频、动图以及插件主动设计的内容动画不受这一条限制。

## 4. 开放程度：可以修改整个灵动岛

请将以下作为明确需求，而不是只提供几个固定槽位：

- 调整灵动岛整体宽高、比例、位置、外形、圆角、边界和可见区域。
- 添加、删除、隐藏、替换原生场景内容，并支持恢复。
- 自由放置图片、视频、动图和功能组件，支持嵌套、组合和父子关系。
- 调整坐标、尺寸、缩放、旋转、透明度、颜色、层级、裁剪和布局。
- 为皮肤内容添加点击、拖动、滚轮、键盘等行为。
- 可保留原生音乐、通知等内容，也可通过明确的替换规则重新布局或绘制。
- 多个插件同时生效时，修改关系可解释、可追踪、可单独撤销。

不要把此前“时间显示插件默认不改变岛大小”的个别插件要求，变成整个插件系统不能改变尺寸的限制。时间插件可以保持克制，皮肤插件可以主动修改整体尺寸和布局。

普通挂件默认可不扩容；皮肤插件应能主动选择控制尺寸和布局。不要为每次尺寸修改增加用户确认，也不要通过固定尺寸白名单重新限制布局自由。

用户希望接近模组加载器的自由度，但公开 API 必须有清晰的线程、资源归属、句柄有效期和失败行为。保留这些工程规则是为了可靠运行和恢复，不是为了限制皮肤设计。

## 5. 皮肤与插件的关系

皮肤可以作为 `.wimod` 中的一组资源和配置，也可以由插件代码动态生成。优先扩展现有加载体系，避免再建一个互不兼容的皮肤安装器。

建议支持两种使用方式：

1. **资源皮肤**：图片/动图/视频、布局和样式配置，尽量减少第三方编码量。
2. **功能皮肤**：在资源基础上附加插件逻辑，例如点击时间切换格式、拖动组件、控制媒体、显示状态。

先检查现有加载器是否强制要求 DLL。若支持无代码皮肤需要改变包格式，请明确新增的包类型、解析分支、版本条件和兼容测试。不能在原加载器仍要求 DLL 时宣称“只放 JSON 即可安装”。

第一版可让两种使用方式共用插件入口和资源加载工具；纯资源包属于实际实现后才能宣布支持的能力。

## 6. 图片、动图和视频格式

不要承诺无条件支持世界上所有格式。请以常见格式为覆盖目标，提供可查询、可扩展的格式能力表，并说明不支持格式的原因及后续扩展方式。

### 6.1 静态图片

优先覆盖 PNG、JPEG、BMP、WebP，评估 SVG、AVIF 等扩展格式。说明透明通道、颜色空间、图片方向信息、解码尺寸和失败行为。SVG 是矢量格式，不能当成位图解码器天然支持。

提供原始尺寸、实际解码尺寸、保持比例、contain、cover、拉伸、局部裁剪和资源替换。大图按目标大小解码或缓存，避免不必要的整张超大纹理。

### 6.2 动图

优先覆盖 GIF，并评估 APNG 和动态 WebP。正确处理帧时长、循环次数、透明叠加及帧处置规则。不能只显示第一帧后宣称支持动图。

提供播放、暂停、停止、重新开始、循环和播放速度等控制，说明不支持的操作。隐藏时可以按策略暂停解码或减少渲染，恢复时明确继续原进度还是追赶时间。

### 6.3 视频

优先验证 MP4/H.264，评估 WebM/VP8/VP9、HEVC、AV1 等扩展。区分容器、视频编码、音频编码和解码器，不能根据 `.mp4` 扩展名就判断一定可播。

提供加载、播放、暂停、停止、跳转、循环、当前时间、总时长、结束和失败事件。支持能力允许时提供速度、音量和静音；纯装饰背景建议默认静音。

说明硬件解码支持条件、软件回退和设备丢失处理。透明视频仅在解码和渲染链均支持时列为支持项，普通 PNG 透明能力不代表视频透明能力。

### 6.4 格式能力表

至少列出：格式/编码、使用库、最低系统条件、是否随包提供、是否依赖用户安装编解码器、透明支持、动画支持、音频支持、硬件加速、已验证样本、已知限制。

Windows 原生图像和媒体能力优先评估；WebP/APNG 等缺口再选择适合的库。若引入 FFmpeg 或其他编解码库，记录构建选项、体积、部署和许可证要求。不要为了“格式很多”直接引入与工程不匹配的大型框架。

## 7. 正式媒体 API

可扩展现有场景接口，或通过 `queryInterface` 新增独立媒体扩展。接口名和类型名属于待设计内容，不能在文档里写成已经存在。

至少需要以下操作契约：

| 操作 | 必须说明的内容 |
| --- | --- |
| 能力查询 | 支持的来源、格式、编码、控制操作和渲染方式 |
| 创建/加载资源 | 来源、owner、异步状态、失败原因、输出句柄 |
| 查询信息 | 宽高、时长、帧率、音轨、透明度与元数据可用时机 |
| 绑定节点 | 一个资源能否被多个节点共享、引用和释放规则 |
| 更新来源 | 原资源继续显示还是清空、异步结果如何防止覆盖新请求 |
| 控制播放 | 播放、暂停、停止、跳转、循环、速度、音量和静音 |
| 状态订阅 | ready、playing、paused、ended、error、seek 完成 |
| 释放 | 取消解码、释放引用、GPU 资源、回调和句柄 |

明确命令接受成功与实际播放成功的区别。快速连续切换来源时使用请求标识或 generation，避免旧请求完成后覆盖新的皮肤。

结构体带 size/version，UTF-8 字符串，明确缓冲区和资源所有权。跨 DLL 不传 STL 对象或未约定的渲染器内部指针。

媒体通常由宿主持有解码和 GPU 资源，插件通过句柄控制；共享资源采用引用计数或等价机制，关闭一个使用者不能使其他使用者的资源失效。

## 8. 场景布局、外形和内容替换

新增图片、动图和视频节点必须进入现有场景树，支持父子变换、透明度、裁剪和层级，与文字、形状、按钮一起渲染。

区分局部 DIP、屏幕物理像素、窗口尺寸、视觉形状和输入区域。扩大皮肤时同步处理渲染目标、窗口范围与命中测试；缩小时避免留下透明但挡点击的区域。

提供整体皮肤模式或等价能力，使插件能调整根尺寸、外形和内容组织。需要实现哪些根属性必须逐项核查，不能保留返回 unsupported 的旧代码却在新文档里宣称任意缩放、旋转均可用。

支持透明背景和非矩形视觉效果；说明圆角裁剪、遮罩、超出父节点绘制、点击穿透区域的具体行为。

原生内容提供稳定标识和可查询语义。允许插件隐藏或替换音乐、歌词、通知、进度、按钮等场景元素；不要写死“媒体永远不能覆盖原生内容”。提供合理默认层级和冲突规则，开发者可以明确选择覆盖或避让。

普通挂件与整体皮肤是不同使用方式，API 应同时支持。多个皮肤争夺根布局时按清晰的优先级或活动皮肤规则解决，不依赖随机加载顺序。

## 9. 功能组件与交互

图片、视频、动图均可成为交互目标，也能在上方添加按钮、文字、滑块和自定义控件。每个节点可选择接收输入、阻止穿透或作为纯装饰。

至少实现并说明：指针进入/离开、移动、按下/抬起、点击、滚轮、拖动开始/更新/结束/取消、键盘焦点与焦点丢失。

拖动分为移动皮肤组件、拖动整体灵动岛、拖动功能滑块。坐标和事件应明确区分，避免拖进度条时移动整个窗口。

实现宿主管理的 pointer capture：指针移出节点、移出窗口、失焦、插件禁用或节点删除时均能结束或取消拖动。不要依赖鼠标一直停留在初始矩形中。

命中测试与渲染变换一致，处理旋转、缩放、裁剪、遮罩和层级。透明像素命中如支持要明确阈值；如只支持几何区域应如实写明。

明确事件捕获/冒泡或当前分发规则、消费返回值和默认动作。支持键盘访问基本功能；触摸、手写笔、IME、全局快捷键等扩展分别列出支持状态，不把键盘事件等同于完整输入法支持。

需要调用宿主功能的按钮应使用明确命令接口，例如播放/暂停、切歌或切换视图，而不是用函数地址偏移控制主程序。

## 10. 线程、播放状态与性能

统一设计加载、解码、帧调度和渲染之间的关系。文件读取与解码不阻塞主 UI 和插件回调线程；渲染线程不直接执行插件 DLL 的任意业务回调。

资源状态应至少区分 loading、ready、playing、paused、stopped、ended、error、released。部分状态仅适用于视频/动图时要说明。

取消加载和插件关闭必须阻止后续回调进入已经卸载的 DLL。解码任务结束、待发布帧、GPU 资源和 owner 引用有明确销毁顺序。

隐藏播放策略可配置：暂停、继续时间但不绘制、继续音频或完整停止。不能一律隐藏就暂停，导致音频类功能中断；装饰视频可默认暂停以节约资源。

限制解码队列和待渲染帧队列，及时丢弃过期帧。缓存复用，避免每帧创建解码器、读取整个文件、创建纹理或打印日志。

建立可配置资源预算和超限反馈；不要沿用旧位图 2048×2048 等限制而不评估新媒体用途，也不要完全取消内存保护。高分辨率视频可按显示尺寸缩放解码。性能结论以实际测量为准。

## 11. 来源、包与持久化

第一版优先完成包内媒体、插件数据文件、用户选择的本地媒体。网络 URL 作为明确的可选扩展，若实现必须有超时、取消、缓存和离线行为，不能把联网作为本地皮肤必需条件。

包内路径使用相对路径，防止解压越界。用户通过文件选择器授权的绝对路径与恶意包内绝对路径是不同情况，分别校验，不要一概拒绝正常的本地媒体选择。

`.wimod` 保持单文件分发，内部可包含 DLL、清单、布局和 assets。用户导入后宿主自动处理资源，无需手动解压。

新媒体可能超过旧包体或单文件上限。阅读包解析器后评估并同步更新上限、提示和测试，记录兼容影响。不要只改媒体 API 而忘记安装阶段会拒绝大文件。

缓存与用户设置分离。卸载是否保留用户选择的路径、布局和播放配置应沿用产品规则；绝不能删除用户原始媒体文件。更新与回退保留旧包和必要配置备份。

## 12. 资源撤销和多插件共存

所有节点、属性覆盖、媒体、事件、定时器、输入捕获和异步任务有 owner。

关闭 A 插件只撤销 A 的贡献。主程序在当前真实基线和剩余插件修改上重新计算，不保存一个启动时旧场景整体覆盖回去。

共享媒体资源在最后一个引用释放后销毁；异步解码完成时检查资源和 owner 是否仍有效。

重新启用应完整恢复该插件，不能依赖 onLoad 一定再次执行。重复禁用、失败启用、卸载和宿主退出都要幂等。

存在真实依赖或跨插件父子关系时，明确关闭顺序、孤立节点和恢复行为；无依赖插件不能被连带停止。无法自动保持某个依赖功能时清楚提示原因。

## 13. 设置与状态诊断

皮肤插件自己的设置可包含来源、皮肤选择、尺寸、位置、布局、播放方式、循环、静音、音量和性能策略。复用现有类型化设置体系；缺少的类型或变更通知应正式扩展。

首次默认值与用户保存值分开，更新和重启保留选择。设置变更必须影响实际场景，不能仅写配置文件。

日志按插件、资源、节点和请求标识定位问题，覆盖导入、格式识别、解码、播放、渲染提交、输入和释放阶段。重复错误限频，不逐帧刷屏。

诊断工具应能看到实际节点、资源状态、布局、正在生效的属性 owner、播放状态和错误。区分成功注册、成功解码、成功提交与真实屏幕显示。

## 16. 示例与验收
