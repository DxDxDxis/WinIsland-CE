## 1. 交接目标与执行边界

目标是让“时间显示”作为真正依赖 WinIsland 主程序运行的插件，在重构后仍能正确加载、显示、配置、关闭、卸载和重新启用，并最终能够交付给普通用户一个完整的 `.wimod` 文件。

需要保留的是用户可观察的行为和可靠的插件契约，不要求重构后继续使用完全相同的内部类名、文件名或渲染实现。底层可以调整，但必须明确哪些接口保留兼容、哪些需要重新编译，以及旧配置如何迁移。

本文中的内容分三种：

- **现有事实**：从本次读取的源码、清单或压缩包直接核实的内容。
- **目标要求**：下一位开发者需要达到的行为，不能因为写进文档就视为已实现。
- **待验证项**：需要在重构后的真实宿主中构建、运行和观察的内容。

将来执行适配时，应在新的插件工作目录中操作，保留旧源码、旧 `.wimod` 和日常配置。宿主代码的额外修改要遵循届时交给该 AI 的任务范围，不要为了通过一个插件测试直接改动日常使用的发布目录。

## 3. 插件身份、元数据与完整功能要求

### 3.1 身份信息

| 项目 | 约定 |
| --- | --- |
| 插件 ID | `time-display` |
| 显示名称 | 时间显示 |
| 作者 | daxian |
| 版本 | `1.0.0`，没有另行要求时不要自行修改 |
| 功能简介 | 一个能让 WinIsland 在待机状态显示实时时间的插件。 |
| 入口 | `bin/time-display.dll`，如重构后必须变更则同步清单 |
| 分发格式 | 单个 `.wimod` 文件 |
| 运行方式 | 由主程序加载，不提供独立 EXE |

用户早期所说“作者简介”实质上描述了插件功能，当前清单保存为 `description`。当前已核对的解析器没有专门的作者个人简介展示字段，不要虚构一个字段并宣称管理界面已经支持。

插件 ID 和设置 key 影响配置归属。仅为重新构建而改 ID，会导致旧配置、启用状态和日志关联断开。版本号保留 `1.0.0` 时，用构建记录与 SHA256 区分不同包；后续正式发布的版本递增另行约定。

### 3.2 时间展示

显示 Windows 当前本地日期和时间，例如：

```text
2026.9.21 12:05
```

- 年、月、日之间用英文句点 `.`。
- 月、日不强制补零；小时、分钟各两位。
- 使用 24 小时制，不显示秒、星期、农历或额外图标。
- 日期与时间之间一个普通空格。
- 默认不要新增背景卡片、按钮、动画、独立窗口或占用输入。
- 文字在灵动岛内显示，大小适中，不主动扩大、移动或改变灵动岛外形。
- 宿主退出后插件一起停止，不留下后台进程或悬浮窗。

### 3.3 显示条件

时间仅在真实待机且没有应优先显示的内容时出现。音乐、歌词、通知或展开内容出现时隐藏；这些内容结束且回到待机后恢复。

当前插件还把“设置窗口打开”作为隐藏条件，适配时保留该行为，避免时间叠加到管理操作期间。音乐暂停不一定代表音乐界面已经消失，不能仅根据“没有播放”判定待机。

用户原始要求强调“什么也没有显示的状态”。其他插件、遥测信息等占用需要结合新宿主的实际场景定义处理，不能把一个粗略 idle 位解释成完整占用判断。具体方法见第 8 节。

### 3.4 设置与管理

- 在本插件自己的设置中提供“显示时间”开关。
- 路径：插件管理 → 时间显示 → 插件设置 → 显示时间；具体界面层级可以随现有管理器命名调整。
- 首次没有保存值时默认开启；用户保存为关闭后，重启、重载、更新均不得擅自开启。
- 设置关闭仅关闭时钟显示，不等同于禁用整个插件。
- 用户后来已限制原生设置界面，不向原生“实时信息”页硬塞按钮，不修改宿主原生设置布局。
- 延续宿主当前插件设置外观；本插件不重新引入页面切换动画。
- 禁用插件时撤销本插件界面、事件和定时器；重新启用必须恢复完整能力。

注意：宿主通过“添加模组”导入新包时，当前实现默认将插件设为禁用。这与插件内部“显示时间默认开启”并不矛盾。用户仍需要先启用插件。

## 4. 当前实现与已确认的问题

### 4.1 已经存在的实现

`src/time-display.cpp` 已经查询 `winisland.scene`，查找 `island`，创建 `WI_TEXT` 元素，设置文本、位置、字号、颜色、透明度、层级和输入标志，并调用 `commit`。

当前节点 key 为 `time-display.text`；设置 key 为 `time-display-enabled`；状态订阅为 `scene.changed`；定时器 key 为 `clock`，间隔 `30000` 毫秒。时间来自 `GetLocalTime`。

这与历史 safe-hidden 包完全不一样。旧包曾经根本没有注册视觉图层，当前源码则已经创建场景文字。不能继续用“从未创建元素”作为当前插件不显示的既定结论。

### 4.2 需要交给重构 AI 的具体问题

| 现有代码事实 | 影响或风险 | 适配要求 |
| --- | --- | --- |
| `load()` 通过设置 API 定义开关，只在加载时读取一次 | 修改设置后，插件成员 `show` 不会因此自动变化 | 必须建立真实的设置变更接收或定期读取路径 |
| `onSetting()` 函数已编写，但未注册为任何资源回调 | 不能因为存在此函数就认为开关即时生效 | 将其实际接入受支持的通知机制，或用明确的读取同步方案替代 |
| `WiSettingsApi.define` 内部创建的资源 callback 为 `nullptr` | 当前类型化设置定义本身不提供插件回调参数 | 不要给该结构体编造 callback 字段 |
| README 声称要求 `WI_IDLE`，实际 `idle()` 只排除 busy 位 | flags 为 0 的初始快照也可能被判断为空闲 | 文档、代码和完整就绪判断必须一致 |
| 宿主 `WI_IDLE` 只由没有音乐和通知推导 | 不涵盖所有其他可见内容 | 补充占用判断或明确限制，不能宣称已解决任意插件避让 |
| 文字矩形固定为 `(18,8,180,24)`，字号 12 | 不同岛宽、高和字体度量下可能偏位或裁切 | 根据实际可用区域布局，验证多种 DPI 和窄尺寸 |
| 每 30 秒刷新一次 | 跨分钟显示可能迟到近 30 秒 | 改为更及时的宿主管理刷新策略 |
| 多个 `scene.set`、删除和 `commit` 的结果未逐项检查 | 可能在属性失败时仍输出“已启用” | 必须识别失败阶段，进行本插件范围的回滚 |
| `apply()` 每次都写可见性并提交，即使没有变化 | 多余发布和提交日志；新事件模型下可能放大回调频率 | 按状态变化写入，按批次提交 |
| 设置注册放在 `onLoad` | 当前宿主禁用会销毁 DLL，通常会重跑加载；若新宿主改为保留 DLL，则设置可能丢失 | 以可撤销资源的实际生命周期安排注册，推荐在启用阶段注册 |
| 工厂要求 `host.size >= sizeof(WinIslandHostApi)` 并整体复制 | 不代表支持任何同 ABI 的旧前缀接口 | 明确最低字段要求和扩展查询，不能用相同 ABI 号代替大小检查 |

以上是静态源码事实与由此推导的风险。本次没有运行窗口，不宣称已重现上述每项可见故障，也没有修复这些代码。

## 5. 主程序插件架构及需要保留的开放性

### 5.1 当前架构

```text
用户选择 .wimod
    ↓
包验证：ZIP、mod.json、路径、依赖、入口 DLL
    ↓
解压到主程序管理的缓存
    ↓
加载 x64 DLL → 校验导出及 ABI → 创建插件对象
    ↓
插件通过宿主接口表查询场景与设置能力
    ↓
加载器工作线程运行回调，保存属于该插件的资源
    ↓
场景变更 commit，宿主复制并发布渲染数据
    ↓
原有渲染器在灵动岛内绘制
    ↓
禁用：停止回调 → 按插件归属撤销 → 清理对象与 DLL
```

`.wimod` 是分发容器，DLL 是当前实现的执行代码，宿主接口表负责与主程序交互。它不是 Java `.jar`，不需要为了单文件分发改用 Java，也不是把文件夹换个扩展名就能成为合格的包。

### 5.2 重构时保留的系统方向

用户需要广泛修改灵动岛内容的能力：添加、隐藏、替换和调整元素、文字、按钮、布局、颜色、效果及交互，不希望再退回“只给时钟一个固定插槽”的局限。

建议保留通用场景模型：元素查找和枚举、属性读取与覆盖、节点创建和删除、输入和自定义绘制、提交与按插件归属撤销。时间显示只是此体系的一个小型使用者。

| 能力 | 当前开放接口 | 重构注意事项 |
| --- | --- | --- |
| 状态和布局查询 | `snapshot` | 提供一致的业务状态、尺寸、DPI、就绪语义 |
| 元素发现 | `find / enumerate / visible` | 区分已注册元素和已进入渲染的元素 |
| 增加、复制元素 | `create / clone` | 明确所有权、父节点和句柄有效期 |
| 修改和替换 | `read / set / clear / remove` | 保留可撤销属性层，避免整体旧状态覆盖 |
| 自定义内容 | `draw / bitmap / onDraw / requestDraw` | 说明支持范围和线程，渲染线程不直接调用 DLL 代码 |
| 输入 | `listen` | 清理回调、处理焦点和事件分发，不影响其他插件 |
| 发布及撤销 | `commit / reset` | 只处理调用插件所属的修改 |
| 插件设置 | `define / read / write` | 保留类型、持久化，并补足变更通知或可用替代方案 |

原生设置界面仍是当前明确的保护范围；插件自身设置不在禁止范围内。

“开放”不等于取消 ABI、线程、数据有效性、资源归属和释放顺序。那些机制是确保插件能协作和撤销的基础。也不能把当前开放场景接口宣传成任意 C++ 函数都能 Hook：旧 `WI_HOOK` 本质上沿用资源事件分发，不等于通用机器码修改接口。

当前公开属性仍有具体边界，例如根节点缩放、旋转、阴影会返回 `WI_UNSUPPORTED`；软模糊阴影尚未实现。重构后如扩大能力，应更新接口版本和适配说明，不要仅改变说明文字。

时间显示本身不需要 QuickJS、V8 或 GSAP，不应为它新增整套脚本运行时依赖。若宿主底层替换动画或渲染模块，只需保证上述文字、状态、设置和生命周期契约仍成立。

## 6. 重构后的兼容性核对

### 6.1 当前接口标识

| 层次 | 当前值 |
| --- | --- |
| 清单 `apiVersion` | 数字 `1` |
| 生命周期 `WINISLAND_MOD_ABI` | `0x00010002u` |
| 场景接口名 | `winisland.scene` |
| 场景扩展版本 | `WI_SCENE_ABI = 1u` |
| 设置接口名 | `winisland.settings` |
| 设置扩展版本 | `1` |

当前导出名字必须是：

```cpp
extern "C" WINISLAND_MOD_API uint32_t WinIsland_ModAbi();
extern "C" WINISLAND_MOD_API IWinIslandMod*
WinIsland_CreateMod(const WinIslandHostApi* host);
```

`extern "C"` 用于避免 C++ 名字修饰。DLL 接口表和对象的内存由插件 DLL 自己分配和释放，宿主调用 `destroy(context)`，不要由宿主直接 `delete` 插件对象。

### 6.2 正确查询扩展的参考片段

以下是当前已核对头文件的调用形状，属于局部示例，不是完整插件：

```cpp
#include <cstddef>
#include "mod_api.h"

bool QueryScene(const WinIslandHostApi* host, WiSceneApi& scene) {
    if (!host || host->version != WINISLAND_MOD_ABI)
        return false;
    constexpr size_t required = offsetof(WinIslandHostApi, queryInterface)
                             + sizeof(host->queryInterface);
    if (host->size < required || !host->queryInterface)
        return false;

    scene = {};
    int result = host->queryInterface(
        host->context, WI_SCENE_INTERFACE, WI_SCENE_ABI,
        &scene, sizeof(scene));
    return result == WI_OK
        && scene.size >= sizeof(WiSceneApi)
        && scene.version == WI_SCENE_ABI
        && scene.snapshot && scene.find && scene.create
        && scene.set && scene.remove && scene.commit;
}
```

真实签名为：

```cpp
int (*queryInterface)(void* context, const char* name,
                      uint32_t version, void* out, uint32_t bytes);
```

不要省略 context、输出表或输出表大小，也不要在读取可选尾部指针之前跳过 `size` 检查。其他宿主函数指针同样要检查。

### 6.3 数据约定

- 结构体先零初始化，再填写 `size`、`version` 和有效字段。
- `WiSceneSnapshot`、`WiPropertyValue` 当前结构版本均为 1；不能统一填生命周期 ABI 数值。
- 字符串为 UTF-8，调用期间有效，由宿主复制。固定字符数组必须以 NUL 结尾。
- `WiPropertyValue.text` 为 1024 字节，容量按字节而非中文字符数量计算。
- API 输出使用调用方缓冲区，不能让宿主写入无效或过小的内存。
- 不跨 DLL 传递 STL 容器、C++ 引用、异常或需要另一方 CRT 释放的对象。
- 不擅自改变结构体对齐、字段顺序、枚举值、调用约定或指针宽度。
- 重新构建时使用目标宿主提供的完整 SDK，不能只复制一个头文件后手写另一个。

### 6.4 适配结果必须明确

重构后的 AI 应给出“旧能力 → 新接口 → 语义差异 → 验证方法”的映射。

如果 ABI 不兼容，就以新 SDK 重新编译，并明确旧 `.wimod` 不保证可用；如果保留旧 ABI，就需要兼容层测试。不能通过伪造旧版本号或绕过大小检查来强行加载。

对于不支持场景或设置接口的宿主，应清楚报告不兼容，不能显示“已启用”却永久不显示时间。

## 7. 生命周期与资源撤销

### 7.1 当前真实关闭顺序

本次读取的 `mod_system.cpp` 中，关闭大致按以下顺序执行：

1. 将该插件 `accepting` 设为 false，停止后续正常回调准入。
2. 执行宿主现有的过渡处理。
3. `revoke` 撤销所属场景内容、输入、绘图绑定和资源。
4. 调用插件 `onDisable`。
5. 调用 `onUnload`、`destroy` 并释放 DLL。

当前实现的普通禁用分支同样会销毁 DLL，并非保证保留 DLL 到卸载时才释放。另一方面，重构后可能选择保留 DLL，所以不能把“每次启用必定重新 onLoad”写成永久约定。

`sceneCall` 在 `accepting == false` 时返回 `WI_STOPPED`。因此 `onDisable` 或 `onUnload` 再调用场景删除、提交，可能被拒绝；宿主已先行撤销时这不代表资源泄漏。插件必须清空本地句柄，不能无限重试清理 API。

### 7.2 推荐职责划分

| 阶段 | 插件职责 |
| --- | --- |
| 工厂创建 | 校验接口表，分配对象，初始化全部字段，返回完整回调表 |
| `onLoad` | 查询兼容接口，建立本地状态，不把可撤销 UI 仅绑定在此阶段 |
| `onEnable` | 注册设置和观察资源，读取持久化值，创建初始隐藏节点，完成首次刷新 |
| 状态/定时回调 | 读取新状态和设置，计算目标文字及布局，仅提交变化 |
| `onDisable` | 标记停止、清空缓存和句柄；API 仍可用时做自身清理，已撤销时接受已停止状态 |
| `onUnload` | 幂等释放剩余本地资源，不重新注册，不访问失效宿主对象 |
| `destroy` | 由插件自己的 CRT 销毁对象 |

### 7.3 幂等与失败回滚

- 重复启用不能出现两个时钟节点或多个刷新定时器。
- 重复关闭、卸载和清理不能崩溃。
- 注册到一半失败时，撤销已经注册的本插件资源。
- 节点创建成功、属性失败、事件失败、定时器失败、提交失败均要覆盖。
- 不依赖“返回失败后一定调用 onDisable”；当前加载失败路径会撤销并销毁，插件本地析构仍要可靠。
- 句柄释放后置零；字符串缓存、已提交可见状态和布局缓存一并重置。
- 不能销毁一个工作回调仍可能引用的插件对象。

当前 API 回调在加载器工作线程串行执行，头文件约定不使用插件自建线程。优先使用 `WI_TIMER` 和宿主管理事件。若新宿主改为并发模型，必须重新说明回调与关闭之间的同步，而不是默认旧代码天然线程安全。

## 8. 待机判断、其他内容与状态变化

### 8.1 当前宿主的真实 idle 含义

`app.cpp` 的 `WI_IDLE` 来自：

```cpp
!scene.music && !scene.notice
```

所以它不是“全部元素为空”的完整证明，设置窗口、展开状态、其他插件内容等还需要单独判断。

最低显示判定应包括：插件处于启用阶段、显示设置开启、快照有效且已就绪、有 `WI_IDLE`，并且不存在下列 busy 位：

```text
WI_MUSIC | WI_PLAYING | WI_LYRIC | WI_NOTICE
| WI_IS_EXPANDED | WI_SETTINGS_OPEN
```

没有 `WI_PLAYING` 不代表没有音乐；播放暂停时仍可能保留音乐卡片。`flags == 0` 也不能直接解释成“已确认待机”。

### 8.2 状态变化处理

当前宿主实际发布了以下相关事件：

- `scene.changed`
- `scene.idle`
- `scene.music.started / changed / stopped`
- `scene.lyric.started / changed / stopped`
- `scene.notice.shown / hidden`
- `scene.expanded / collapsed`
- `scene.layout.changed`

时间显示可用 `scene.changed` 处理业务状态，补充 `scene.layout.changed` 处理布局；由定时器兜底检查。不要重复订阅大量等价事件后又无条件重复提交。

事件是重新读取快照的提示，不能依赖“我记住了最后一条开始事件”维持永久状态。事件可能合并或排队，插件可能中途启用，必须从新快照推导最终状态。

### 8.3 其他插件与遥测占用

目标是不给其他内容添遮挡，不要求时间插件强制管理其他插件。

如果新宿主有明确的“内容占用 / 活动场景 / 保留区域”契约，优先使用，并要求能排除调用插件自己的节点。

如果沿用当前 API，可在需要时结合 `visible` 和节点 owner、key、类型及有效区域判断。必须说明：

- `island` 根容器和基础背景本来就一直存在，不能算成繁忙内容。
- 排除本插件自己的节点，否则时钟出现会让自己判断成占用并隐藏，再恢复，形成闪烁。
- 排除已隐藏、全透明或有效区域为零的内容。
- 其他插件可见内容、FPS / ping 等遥测需要有明确避让策略。
- 不要只靠文字内容、固定数量或私有内存偏移猜测占用。
- 几何相交只能说明可能重叠，无法自动判定内容语义。无法准确分类时应记录限制，提出宿主状态契约的补足点。

当前 `visible` 表示宿主最近回传的渲染节点及裁剪后区域，不是当前 `create` 后立刻可用的同步屏幕证明，也不保证节点没有被更高层内容遮挡。不能收到空数组就马上认定首次启动时没有内容。

### 8.4 generation 和句柄

`enumerate / visible` 接受 generation；非零且与当前快照不一致时返回 `WI_CONFLICT`。应重新取快照后有限重试，不进行无限循环。

处理 `WI_LIMIT` 时查看总数和缓冲区容量，不使用被截断的数组得出“其余没有内容”的结论。父节点过滤也不是天然递归查找。

节点 key 可用于重新定位，数值句柄不能跨 DLL 重载或主场景重建永久保留。`WI_NOT_FOUND` 可能意味着目标暂时不存在或句柄失效，应清除缓存并在合理时机重建自己的节点。

### 8.5 防止自触发循环

维护最后成功提交的文字、可见性和布局；有变化才 set，有实际写入才 commit。

当前源码不能据此断言已经存在无限 `scene.changed` 循环；这是重构后扩大事件范围时需要防止的风险。不要把风险描述成已经复现的 bug。

## 9. 时间计算、刷新和性能

### 9.1 时间来源

每次需要更新时重新读取 Windows 本地时间，不使用自增分钟计数器推算当前时间，不把快照中的单调运行时间直接当成本地年月日。

格式化参考当前实现：

```cpp
SYSTEMTIME t{};
GetLocalTime(&t);
char text[32]{};
sprintf_s(text, "%u.%u.%u %02u:%02u",
          t.wYear, t.wMonth, t.wDay, t.wHour, t.wMinute);
```

需处理午夜、月底、年底、闰日、手动调整时间、切换时区以及休眠恢复。恢复后读取真实时间，不补跑睡眠期间每一个 tick。

### 9.2 推荐刷新策略

在当前 API 没有分钟边界调度和设置变更订阅的前提下，可使用一个约 1000 毫秒的宿主管理定时器：读取本插件设置、必要状态和时间，仅在显示字符串、可见性或布局变化时提交。

这样可以把正常情况下跨分钟的显示延迟控制在约一个检查周期，而不是现有 30 秒。真实响应还受宿主负载影响，测试时记录实际延迟，不承诺硬实时。

若重构后具备可靠的设置通知、时间变化通知和分钟边界调度，也可采用事件结合按需刷新；不需要为了时钟实现复杂调度框架。

“不显示秒”是格式要求，不等于禁止每秒执行一次轻量检查。每秒重新创建节点、字体或整个页面则不合适。

### 9.3 关闭设置时的取舍

如果没有设置事件，关闭显示后不能把唯一的设置轮询也停掉，否则用户重新开启设置时插件无法得知。

可以保留一个低成本宿主定时器负责发现设置变化，关闭时不做不必要的文字更新和场景提交。禁用整个插件时才撤销全部观察资源。

### 9.4 性能边界

- 不做磁盘扫描、网络请求、窗口遍历或 DLL 重载来获取时间。
- 不自行循环 sleep，不阻塞加载器工作线程。
- 不每秒写 XML；设置只在实际修改时持久化。
- 不重复追加属性层、事件和节点。
- 日志按状态变化输出；重复失败限频。
- 对比启用前后 CPU、内存、节点数、资源数和提交次数，采用测量结果，不声称“绝对零损耗”。

## 10. 文字布局、渲染和输入

### 10.1 坐标与尺寸

普通节点 `WI_RECT` 使用父节点相对 DIP，数值次序为 x、y、width、height。当前渲染器会应用父级变换、锚点和内边距，不要再手动乘一次 DPI 或 MusicScale。

根节点屏幕位置 `WI_POSITION` 是另一套语义，不能与文字局部坐标混用。时间插件不需要修改根节点位置。

根据实际可用宽高设置文字区域，保留水平边距，并适当居中。参考字号可以从 12 DIP 起验证，但不能把旧固定矩形当成所有尺寸都适配的保证。

需要同时验证短日期 `2026.1.1 00:00` 和长日期 `2026.12.31 23:59`，避免长日期换行、裁切或偏移。选用系统已有字体和合理回退，不要求用户额外安装字体。

如果当前尺寸确实无法容纳完整格式，应说明最小支持尺寸或采用经过验证的缩小策略，不自动放大灵动岛来掩盖问题。

### 10.2 不改变宿主布局

不要注册旧 `WI_LAYER / WI_BUTTON` 作为时钟显示层，它们历史上会进入 footer 并增加高度。

直接使用开放场景中的文字子节点，不写宿主根节点尺寸、外形、位置或全局布局模式。

特别注意：当前 `WI_SIZE_MODE` 只允许设置根节点。不要为了表示“这是覆盖文字”把 `WI_OVERLAY` 写到普通文字节点上；也不要每次启用强制设置根节点为 Overlay，覆盖别的插件的布局决定。应通过不申请额外布局空间实现本插件默认不增高。

如果其他插件已修改根尺寸或布局模式，时间插件按有效尺寸适配，并避免加入参与 Intrinsic 扩容的布局内容。

### 10.3 首帧与提交

创建节点后先配置隐藏状态和全部属性，再根据快照决定首次显示，避免占位文字或默认 100×24 的节点闪过。

检查每次关键 API 结果。只有必要属性完成并提交成功，才能报告“已创建并提交时钟”；屏幕确实可见还需要渲染验证。

`create / set` 修改的是待提交数据，必须 `commit` 才发布。`enumerate / read` 可能看到待提交状态，不能代替渲染验证。

### 10.4 层级和输入

- 使用普通文字节点，不使用按钮节点冒充文字。
- `WI_RECEIVE_INPUT = 0`、`WI_BLOCK_INPUT = 0`。
- 不注册焦点、快捷键或输入回调，不覆盖岛的点击和拖动。
- 不用极高层级把时钟强行置于通知和歌词上方；通过显示条件避让。
- 不新增白底、边框、悬停块或选中框。
- 在硬件渲染和宿主软件回退路径中验证文字。

## 11. 显示时间设置与旧配置迁移

### 11.1 当前设置契约

```text
接口：winisland.settings，版本 1
key：time-display-enabled
label：显示时间
type：WI_SETTING_SWITCH
defaultValue："1"
minimum：0
maximum：1
```

当前声明如下：

```cpp
typedef struct WiSettingsApi {
    uint32_t size, version;
    void* context;
    int (*define)(void*, const WiSettingDefinition*, uint64_t*);
    int (*read)(void*, const char* key, char* out, uint32_t bytes);
    int (*write)(void*, const char* key, const char* value);
} WiSettingsApi;
```

`define` 返回的句柄是宿主管理资源，不是 Win32 控件句柄。

### 11.2 当前缺少的通知链

当前 `WiSettingDefinition` 没有 callback 字段。`settingDefine` 以空回调创建资源；`settingWrite` 保存、更新并发布，但没有自动调用插件内那个未注册的 `onSetting` 函数。

因此适配只能选择真实存在的办法：

1. 在保留当前 SDK 的情况下，将设置接口保存为插件成员，并在托管刷新中重新 `read`；值变化后应用。
2. 新宿主若增加正式的设置变更订阅，则使用它，并测试取消订阅和重启恢复。

不要编造已存在的 `settings.changed` 事件。不要重复注册同 key 的旧 `WI_SETTING` 来强行挂回调：当前加载器会拒绝同 owner、同 kind、同 key 的重复资源。

### 11.3 持久化与迁移

当前宿主在每插件的数据目录保存 `settings.xml`。插件通过 API 读写，不直接修改 XML 或硬编码实际安装盘符。

旧包曾使用 `true/false` 或 `1/0` 文本；新类型化开关的写入校验仅接受 `"0"` 或 `"1"`。

当前 `define` 会保留已有设置值，并不自动把旧 `false` 规范化。新插件需要：

1. 定义设置并读取保存值。
2. 将历史 `true/false`、`1/0` 解析为明确布尔值，可兼容大小写和前后空白。
3. 需要迁移时通过有效接口写回规范的 `"1"` 或 `"0"`。
4. 保留用户原本关闭的意图，不把无法解析的值默认为开启。
5. 无效值或读取失败时隐藏并记录原因；后续可恢复时再尝试。
6. 设置缺失时才采用首次默认值，与读取异常区分。

推荐普通交互下在一个约 1 秒的检查周期内响应开关；若使用事件可更快。实际验收要在真实插件设置界面操作，而不是仅检查 XML 文件改变。

### 11.4 资源 key 的规则

`time-display-enabled` 是当前可用设置 key。旧资源注册器对设置和定时器采用字母、数字、短横线、下划线规则，不接受句点。

场景节点 `time-display.text` 可以使用句点，因为走的是另一套 API。事件 topic 也有单独规则。不要把场景 key、事件名、清单 ID 和设置 key 的合法字符混为一谈。

## 12. 错误处理、日志和故障定位

### 12.1 返回值不要混用

| 返回值体系 | 约定 |
| --- | --- |
| 场景和设置 API | `WI_OK = 0` 成功，负数表示错误 |
| `host.add` | 非零资源句柄成功，0 失败 |
| `host.remove` | 当前实现 1 表示移除，0 表示未移除 |
| 旧 `host.getSetting` | 当前实现 1 表示读取成功，0 失败 |
| 生命周期和普通资源回调 | 0 成功，非零会被加载器视为失败 |

不能对所有 API 统一使用 `if (result)` 表示成功。

### 12.2 主要错误

| 错误 | 处理方向 |
| --- | --- |
| `WI_INVALID` | 检查参数、范围、句柄用途和终止字符串 |
| `WI_NOT_FOUND` | 区分暂时缺少目标、过期句柄、缺失设置 |
| `WI_VERSION` | 核对结构体 size/version 和 SDK，不强制调用 |
| `WI_THREAD` | 修正调用线程，不在错误线程继续操作 |
| `WI_STOPPED` | 关闭期间停止操作并清空本地状态；正常运行中记录生命周期异常 |
| `WI_LIMIT` | 处理容量或配额，不无限重试和增加资源 |
| `WI_UNSUPPORTED` | 给出最低能力要求，不假装功能正常 |
| `WI_CONFLICT` | 核对 generation、重复 key、层次循环等具体操作语境 |

暂时非待机或布局未准备好不是插件错误，应隐藏并等待；不能随手返回非零导致整插件被宿主关闭。

### 12.3 建议日志

应能区分这些阶段：

```text
[compat] scene/settings 接口版本与查询结果
[enable] 设置、节点、事件和定时器注册情况
[setting] 值来源：默认 / 已保存 / 旧值迁移；当前开关状态
[visibility] 显示或隐藏及原因：音乐 / 通知 / 设置 / 未就绪 / 占用
[layout] 可用尺寸、文字区域、DPI；仅变化时记录
[scene] 操作名称、节点 key、错误码、generation
[disable] 清理阶段、宿主是否已撤销、剩余本地句柄
```

避免每秒输出“正常”；当前 `scene.commit` 自带日志，所以减少无效提交也可以减少日志噪声。日志中不要出现与结果不符的“全部成功”。

### 12.4 不显示时间的排查顺序

1. 是否加载了指定 EXE 和指定哈希的包，而不是旧包或另一个安装目录。
2. 包是否真正启用；导入默认禁用是否被误解。
3. DLL / ABI / 工厂 / onLoad / onEnable 哪一阶段失败。
4. 设置值是否仍为用户此前保存的关闭。
5. 快照 flags、就绪状态和可用尺寸是否符合显示条件。
6. 是否成功创建自己的文字节点，属性是否写成功。
7. 是否 commit 成功，是否出现有效渲染区域。
8. 是否被父节点隐藏、透明度、裁剪、层级或其他内容影响。
9. 首次显示、分钟更新、回到待机、设置切换分别是否生效。

没有证据时不要直接猜测“API 限制太多”“文字颜色不对”或“被遮盖”。

## 13. 多插件共存与恢复

### 13.1 所有权

当前接口 context 由宿主绑定到插件记录，调用者不传入可伪造的 owner ID。所有节点、属性覆盖、输入、绘图和资源都应保留该归属。

场景 `reset` 只撤销本插件场景内容，不替代旧资源表中的设置、定时器、事件的全部清理；宿主总 revoke 才覆盖这些资源。

### 13.2 恢复模型

当前属性覆盖按 priority 和 sequence 决定生效项。同 owner、同目标、同属性的新写入替换旧层。

禁用某插件时删除它自己的修改层，再根据当前宿主基线和其余插件的有效修改计算结果。不要保存启动时整个场景，然后关闭时把旧快照整块写回。

`remove` 自己创建的节点表示删除；对宿主或其他插件节点调用 `remove` 则是添加本插件可撤销的隐藏修改，不代表取得对方对象的释放权。

时间插件原则上只操作自己的时钟节点和设置，不需要隐藏、删除或替换音乐、通知和其他插件。

### 13.3 独立关闭和依赖

时间插件当前 `dependencies` 为空，应当可以独立关闭，不连带停用无关插件。

宿主存在真实依赖时，关闭被依赖插件可能被拒绝或需要明确的连带关闭选择。不能承诺有强依赖时仍让依赖者无条件正常运行。重构时要保留依赖判断，不把无关插件一起重建或关闭。

跨插件父子节点是另一种关系：别的插件若把子节点挂在将被移除的节点下，该子节点可能暂时无法显示。应明确父节点失效和重挂接机制，不能把这类后果描述成完全不存在。

### 13.4 可逆的实际范围

宿主管理的场景层和资源可按 owner 撤销。文件写入、网络请求和任意原生内存修改不自动可逆；同进程 DLL 的严重内存破坏也无法靠普通 try/catch 保证隔离。

因此本插件通过正式接口实现展示和设置即可，不使用内存扫描、函数地址偏移或原生设置窗口注入。宿主检测到慢回调后记录日志，不等于能抢占并安全终止原生死循环。

## 14. .wimod 清单、结构和加载流程

### 14.1 当前完整清单


当前解析器硬性检查合法 ID、数字 apiVersion 为 1，以及存在入口字段和有效 DLL。名称、作者、简介和版本有缺失回退文本；本插件交付时仍应完整填写，避免把“解析器允许缺省”当成可以省略身份信息。

ID 长度不超过 80 个字符，只用 ASCII 字母、数字、短横线和下划线。中文放在显示名称，不放在 ID 中。

`gameVersion` 是可选的实际宿主版本约束，不是自由说明文本。当前匹配器支持自身实现的比较条件，不应假定支持 npm 的 `^`、`~` 或 `||` 语法；添加前阅读目标版本解析器。即使产品版本范围匹配，也仍需查询开放场景扩展能力。

依赖可为 ID 字符串或含 id/version 的对象，但时间插件目前没有其他模组依赖。不要把 `kernel32.dll`、SDK 头文件或 GSAP 写成模组依赖。

```text
└─ bin
```

- 使用真正的 ZIP 内容，以 `.wimod` 作为分发扩展名。

- 不包含盘符、绝对路径、`..`、反斜杠路径、符号链接或重复路径。
- 不把 RAR / 7z 文件直接改名为 `.wimod`。

当前解包器的边界包括：包体最大 128 MiB，单文件最大 64 MiB，总解压最大 256 MiB，最多 4096 个条目，清单最大 256 KiB。这些是当前实现限制，未来改动时同步文档。时间插件应远小于这些上限。

### 14.4 单文件分发不等于运行不落地

用户只需要获得一个 `.wimod`，但当前宿主会将其解压到受管理缓存后加载 DLL。

```text
<dataRoot>\mod-cache\time-display\1.0.0\<包SHA256>\bin\time-display.dll
```

配置和日志位于另一条数据路径：

```text

<dataRoot>\mods\time-display\host-state.txt
```

`<dataRoot>` 由宿主确定，可以受部署或测试配置影响。不要硬编码 D 盘、EXE 同目录或旧诊断中的用户目录。缓存里的解压副本正常存在，不代表单文件插件方案失败。
