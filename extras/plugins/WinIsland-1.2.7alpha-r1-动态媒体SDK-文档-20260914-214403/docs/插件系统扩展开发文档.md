# WinIsland 插件系统扩展开发文档

## 文档范围

本文档面向扩展 API、宿主实现和未来官方版本维护者，说明如何在不破坏旧插件的前提下扩展场景、渲染、输入、设置和动画能力。当前基线为 `1.2.6alpha-c2-open-scene`，语言和图形架构为 C++20、MSVC x64、Win32、DirectComposition、Direct2D、DirectWrite、D3D11。

## 扩展分层

生命周期层保持 `0x00010002` 和原函数表前缀；能力层通过 `queryInterface` 独立演进；场景层负责节点和属性；渲染层负责复制后的命令；输入层负责最终几何命中；设置层负责插件专属持久化。新增功能必须连接完整调用链，不能只添加枚举、头文件或空函数。

## 接口演进规则

所有结构带 `size/version`，调用者先检查表大小和版本。新增字段只能追加，旧字段顺序不得改变。缺失能力返回 `UNSUPPORTED`，无效对象返回 `NOT_FOUND`，代次冲突返回 `CONFLICT`，资源超限返回 `LIMIT`。字符串由宿主复制；不跨 ABI 传递 STL、异常、虚表、线程句柄或 GPU 对象。

## 场景存储与提交

场景存储区分宿主基线、每个 owner 的属性层和当前有效快照。插件调用 `create`、`set`、`clear`、`remove` 后只修改暂存计划，`commit` 才发布。发布时生成新代次，App 合并业务状态和尺寸，Renderer 消费复制后的数据。每个属性按 priority 再按 sequence 选取有效层。

## 元素与布局扩展

新增元素必须说明属性、默认值、绘制、测量、命中、可访问性、序列化和撤销行为。根节点尺寸模式必须与窗口定位、DPI、输入区域和 DirectComposition 提交一致。Intrinsic 只能在测量实现完整时开放；不完整的自动布局应返回限制并让插件使用 PluginManaged。

## 绘图与输入扩展

宿主拥有图形设备和渲染线程，插件只能提交复制的命令、位图或受控 CustomDraw 数据。输入命中必须使用与绘制相同的变换、裁剪和 z 顺序。新增输入类型要定义捕获、焦点、取消、事件代次和未处理事件规则。完整 IME、剪贴板、系统快捷键和任意 HWND 不应通过临时指针暴露。

## 设置、动画和资源

设置 API 应独立于原生设置框架，验证类型、范围、选项和持久化错误。动画可以写入通用场景属性，但必须服从 owner、代次、取消和 reduced-motion 规则；本版设置界面保留参考分支行为，不受媒体播放策略控制。任何定时器、事件、绘图回调和动画句柄都必须进入资源表，在禁用前停止并确认回调排空。

## 卸载和故障

卸载顺序固定为停止接收、排空工作、清理 owner 资源、发布快照、释放插件对象和 DLL。不得通过整页快照恢复，也不得让渲染线程持有插件内存。宿主只能保护可捕获异常，不能保证任意原生 DLL 崩溃或死循环可恢复。

## 兼容测试

每次扩展需验证旧插件仍能加载、旧资源语义不变、新接口缺失时可回退、两个 owner 的覆盖可重算、节点删除不误伤子树、DPI/窗口变化、输入命中、提交失败、资源上限和退出清理。文档必须区分已实现、实验性和未开放能力。


## r1 媒体扩展

媒体 API 是独立的可选接口表，不改变旧 ABI。宿主负责 WIC/GIF 合成、MF/H.264/PCM 解码、waveOut、像素与队列预算、包内/插件数据/授权本地文件边界和 owner 生命周期；插件负责元素布局与回退。能力以 `WiMediaCapabilities` 为准，未声明格式必须处理 `WI_MEDIA_UNSUPPORTED`。

## r1 媒体/场景的完整适配路径

媒体逐函数合同、结构字段、格式表、预算、输入与示例在《媒体资源与皮肤扩展》，精确头文件在《SDK接口参考》。这些是本手册的组成章节，不是计划。

新增格式步骤：先查系统codec并编写独立正确性样本；在media_runtime的load分支验证真实container/subtype，统一输出不可变PBGRA帧和时间；capabilities只加已连接的位；定义pause/seek/loop和错误；绑定使用既有scene节点，不另建固定槽；完成release/owner/generation和缓存预算；跑真实窗口/软件后端/双owner；最后同步SDK和文档。纯资源无DLL包需新增受版本约束的包分支和测试，r1没有宣称已支持。

新增属性步骤：枚举追加，SceneStore验证参数/范围/适用目标；Renderer和输入逆矩阵同时接入；窗口属性同步App定位/裁剪/输入区域；未实现返回UNSUPPORTED。不要仅删除根属性拒绝分支，否则会形成“设置成功但窗口不变”的假开放。新增拖动kind已接App capture和worker分发，必须测试失焦/节点删除/卸载取消。

媒体线程分工：插件worker上media_host只做校验/排队/快照，MTA worker做WIC/MF/audio，独立STA做用户选文件，UI渲染不可读文件或调DLL。解码输出只更新已提交node的frame槽，不能顺带commit插件尚未提交的其他编辑。事件为最新状态通知可合并，消费者读取info。

诊断：ModSnapshot.media公开owner/id/kind/state/generation/position/frameSequence/audioSamplesSubmitted；--verify的state.txt同时输出SceneElement和Media；日志资源事件带owner/resource/generation，不逐帧scene.commit刷日志。

回归：media-runtime-final.txt、media-host-sdk-final、mods-final、scene-final.txt、animation-final.txt；本地选择/多DPI/软件画面及测试边界见本版报告。修改格式表前必须更新样例、错误路径和卸载验证。
