## 为什么不能采用“先显示、主要内容出现后隐藏”

- app.cpp 的 retarget 为每个 WI_LAYER/WI_BUTTON 分配 footer，并执行 target.h += target.modH；render.cpp 只在 footer 画此图层。改 key、文本、字号不能绕过高度变化。
- music.changed 负载只有音乐 key；没有音乐对象时不发送该事件。notice.received 不提供通知已消失事件。没有公开完整 Scene 快照、settings visibility 或其他插件占用信息。
- getSetting 只能读取本插件持久化设置。动画接口只计算动画数值，不提供文本槽或主程序状态。
- 即使允许首次启用乐观显示，仍会增高、可能在音乐已存在时显示，且无法可靠自动恢复/避让，违反本次仍保留的其他要求。
- 不访问私有内存、窗口文字、诊断 state.txt，不替换音乐或通知文本，不新建悬浮窗，不增加宿主代码。

## 新设置实现

- 类型：现有 WI_SETTING（文本值），不是不存在的 boolean ABI 字段。
- key：`time-display-enabled`。宿主 safeId 不允许设置 key 中出现 `.`；用户建议的 time-display.enabled 会被拒绝。
- label：`显示时间`，默认 `true`；编辑 `true/false` 或 `1/0`，允许外侧 ASCII 空格及大小写。
- 位置：插件模组管理 → 选中时间显示 → 插件设置 → 显示时间 → 编辑值 → 保存设置。当前宿主只提供列表、文本编辑和保存按钮；本次没有伪造复选框或新增独立按钮。
- WI_SETTING 在 onEnable 注册。理由是宿主 disable 会 revoke 所有资源，重新 enable 不一定重跑 onLoad；只在 onLoad 注册会丢失设置行。
- onEnable 读取宿主恢复的已保存值，失败/无效安全关闭并记录原因。
- 关闭：立即撤销 WI_TIMER，清空时间缓存，保留插件设置和两个状态观察事件。
- 开启：立即读取本地时间，创建唯一的 30000ms 宿主管理定时器。**只启用检查，不显示文字。**
- 宿主保存原始字符串后调用回调；插件不自行写主程序文件。无效字符串保留在编辑框供用户改正，运行状态按关闭处理，不用异常退出整插件。
- disable/unload 清理全部自身资源。此处的显示设置处理不调用动画；宿主自己的插件启停淡入流程不属于本次插件可修改范围，不声称已经移除。
